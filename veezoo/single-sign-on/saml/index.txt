15:T18b3,<p>The <a href="https://app.veezoo.com/admin/sso/saml">SAML page</a> in Veezoo Admin lets you configure Veezoo to use Security Assertion Markup Language (SAML) to authenticate users.</p>
<p>Single sign-on with SAML is only available for <strong>Enterprise</strong> subscription plans. Check our <a href="https://www.veezoo.com/pricing">pricing</a> and <a href="https://www.veezoo.com/contact">get in touch</a> with us to enable it!</p>
<h2 id="configure-your-identity-provider">Configure your identity provider</h2>
<p>In a first step, you need to configure Veezoo as a service provider at your identity provider. Check our documentation on how to configure <a href="/veezoo/single-sign-on/saml/microsoft-azure-idp">Microsoft Azure as an identity provider</a> for Veezoo.</p>
<p>The information required and terminology used by your identity provider may slightly differ depending on the specific implementation used. You can view and extract Veezoo's service provider information from the <strong><em>Service Provider</em></strong> subsection:</p>
<p><img src="/img/single-sign-on/saml/service-provider.png" alt="Service provider subsection"></p>
<h4 id="entity-id">Entity id</h4>
<p>The entity id of the service provider, i.e. Veezoo.</p>
<p>This is a globally unique name identifying Veezoo as a service provider. Some identity providers might also call this the <em>identifier</em>, <em>audience</em> or similar.</p>
<p>Some identity providers might also call this the <em>identifier</em>, <em>audience</em> or similar.</p>
<p>Value: <code>https://veezoo.com/saml</code></p>
<h4 id="assertion-consumer-service-url">Assertion consumer service URL</h4>
<p>The URL of the assertion consumer service (ACS) of the service provider, i.e. Veezoo.</p>
<p>This is the URL of the Veezoo endpoint where the identity provider should send SAML assertions to after an authentication. Some identity providers might also call this the <em>callback URL</em>, <em>reply URL</em>, <em>destination</em> or similar.</p>
<p>Value: <code>https://&#x3C;subdomain>.app.veezoo.com/saml/callback</code></p>
<h4 id="metadata">Metadata</h4>
<p>The metadata of the service provider, i.e. Veezoo.</p>
<p>This is an XML object containing all the necessary information to describe Veezoo as a service provier.</p>
<h2 id="enter-your-identity-provider-information">Enter your identity provider information</h2>
<p>Veezoo needs to know about your identity provider, so it can send authentication requests to the right place. You can configure this information in the <strong><em>Identity provider</em></strong> subsection:</p>
<p><img src="/img/single-sign-on/saml/identity-provider.png" alt="Identity provider subsection"></p>
<h4 id="metadata-1">Metadata</h4>
<p>The metadata of the identity provider.</p>
<p>This is an XML object containing all the necessary information to describe the identity provider. Identity providers typically let you download the metadata as a file.</p>
<h4 id="maximum-authentication-lifetime">Maximum authentication lifetime</h4>
<p>The maximum lifetime of an authentication at the identity provider, specified in seconds.</p>
<p>SAML assertions returned by identity providers contain an <code>AuthnStatement</code> with an <code>AuthnInstant</code> attribute. The value of this attribute specifies the time at which the authentication took place at the identity provider. Veezoo rejects SAML assertions with an <code>AuthnInstant</code> value that is older than the configured maximum authentication lifetime.</p>
<h2 id="configure-user-attributes">Configure user attributes</h2>
<p>When a user authenticates via single sign-on with SAML, a corresponding user gets automatically created in Veezoo. The <strong><em>User attributes</em></strong> subsection determines the attributes of that user by defining user attribute mappings against the attributes of the SAML assertion:</p>
<p><img src="/img/single-sign-on/saml/user-attributes.png" alt="User attributes subsection"></p>
<p>A SAML assertion attribute on its own grants nothing - it only takes effect through a mapping that reads it. In particular, you need to define a <strong>Type</strong> mapping, otherwise users are created deactivated and cannot sign in.</p>
<p>Read the <a href="/veezoo/single-sign-on/user-attributes">user attributes</a> documentation for more information.</p>
<h2 id="test-and-save-the-saml-configuration">Test and save the SAML configuration</h2>
<p>After having completed the above steps to configure SAML, you can test and save your configuration. Click on the <em><strong>Test &#x26; Save</strong></em> button to perform an authentication test with the SAML configuration.</p>
<aside class="docs-aside docs-aside--note" data-title="Note"><p class="docs-aside__title">Note</p><p>The authentication test is performed in an authentication <strong>popup window</strong>. Please make sure to instruct your browser to allow popups.</p></aside>
<p>After a <strong>successful</strong> authentication test, a dialog displays the user attributes that resulted from applying the configured user attribute mappings:</p>
<p><img alt="Authentication test result" width="600" src="/img/single-sign-on/saml/authentication-test-result.png"></p>
<p>You can now go ahead and save the configuration.</p>
<p>If the authentication test <strong>failed</strong>, please make sure your configuration is correct or <a href="https://www.veezoo.com/contact" target="_blank">contact us</a> for support.</p>
<aside class="docs-aside docs-aside--note" data-title="Note"><p class="docs-aside__title">Note</p><p>If you save a configuration which you enabled/disabled, or which is already enabled, the page will <strong>reload</strong> after the saving has completed. This is in order for the new authentication method to take effect (if you enabled/disabled the config) or to apply the user attribute mappings to your user (if the config is already enabled).</p></aside>
