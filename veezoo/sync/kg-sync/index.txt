15:T462c,<p>Veezoo uses two types of synchronizations to keep your Knowledge Graph aligned with your database:</p>




















<table><thead><tr><th>Type</th><th>Purpose</th><th>Scheduling</th></tr></thead><tbody><tr><td><strong>Entity Synchronizations</strong></td><td>Keeps entity values (e.g., product names, categories) up-to-date</td><td>Manual or scheduled (configurable)</td></tr><tr><td><strong>Schema Synchronization</strong></td><td>Validates database schema and updates <code>synced_description</code> properties</td><td>Automatic (daily)</td></tr></tbody></table>
<p>Both types of synchronizations are displayed in the <a href="https://app.veezoo.com/studio/synchronization">Synchronization view</a> in Studio. We explain these two types in more detail below.</p>
<h2 id="entity-synchronizations">Entity Synchronizations</h2>
<h3 id="why-keep-your-entities-synchronized">Why keep your entities synchronized?</h3>
<p>The Knowledge Graph is a semantic representation of your data and, because of that, it needs to know the values (entities) in your data.</p>
<p>When we talk about entity synchronization, we mean keeping these database values up-to-date.</p>
<h4 id="what-does-entity-synchronization-mean">What does "entity synchronization" mean?</h4>
<p>To understand the importance of synchronization, let's consider an example. You have a table in your database, where each row represents an order. The existing data might look something like this:</p>

















































<table><thead><tr><th>order_id</th><th>customer_id</th><th>customer_name</th><th>product_id</th><th>product_name</th><th>product_description</th><th>category</th><th>price</th><th>order_date</th></tr></thead><tbody><tr><td>1</td><td>1</td><td>John Doe</td><td>2</td><td>Jeans</td><td>Comfortable blue denim jeans that are perfect for everyday wear</td><td>Clothing</td><td>50</td><td>2023-01-01</td></tr><tr><td>2</td><td>2</td><td>Jane Smith</td><td>1</td><td>T-shirt</td><td>Simple white cotton t-shirt that pairs well with any outfit</td><td>Clothing</td><td>20</td><td>2023-01-02</td></tr><tr><td>3</td><td>1</td><td>John Doe</td><td>3</td><td>Watch</td><td>Durable stainless steel watch with a modern design</td><td>Accessories</td><td>150</td><td>2023-01-03</td></tr></tbody></table>
<p>Let's say your data gets updated, and a new row is added where a new product (e.g. a "Dress") is sold in a new category (e.g. "Formal Wear").</p>



























<table><thead><tr><th>order_id</th><th>customer_id</th><th>customer_name</th><th>product_id</th><th>product_name</th><th>product_description</th><th>category</th><th>price</th><th>order_date</th></tr></thead><tbody><tr><td>4</td><td>3</td><td>Bob Brown</td><td>4</td><td>Dress</td><td>Elegant red silk evening gown with beautiful beading and a dramatic silhouette. Ideal for formal occasions.</td><td>Formal Wear</td><td>100</td><td>2023-01-04</td></tr></tbody></table>
<p>Without syncing, the AI agent and autocomplete don't know about 'Dress' or 'Formal Wear' yet, so these terms cannot be resolved to the right values in your data.</p>
<p>You would want to synchronize your Knowledge Graph so that it is aware of the new product "Dress" and the new category "Formal Wear". This way the AI agent can <em>resolve these terms to the right entities</em> when answering questions like "How many orders of Dresses were there this year?", and the new values show up in autocomplete.</p>
<p>In contrast, if another row is added where an existing customer buys an existing product, like so:</p>



























<table><thead><tr><th>order_id</th><th>customer_id</th><th>customer_name</th><th>product_id</th><th>product_name</th><th>product_description</th><th>category</th><th>price</th><th>order_date</th></tr></thead><tbody><tr><td>5</td><td>1</td><td>John Doe</td><td>1</td><td>T-shirt</td><td>Simple white cotton t-shirt that pairs well with any outfit</td><td>Clothing</td><td>20</td><td>2023-01-04</td></tr></tbody></table>
<p>In this case, there are no new entities that the Knowledge Graph needs to be aware of. So even if a sync did not run since the new order came in, the AI agent still knows the entities 'T-shirt' and 'Clothing' and answers a question about them correctly.</p>
<p>In other words, the Knowledge Graph tells the AI agent <strong>which entities exist - it is not where the answer comes from</strong>. The actual answers to your questions are computed based on the most recent state of your database, using SQL.</p>
<p>The Knowledge Graph will contain the individual distinct values of a database column (e.g. your products), but not all the rows in your database (e.g. all the transactions from these products and the revenue, etc).</p>
<h4 id="what-should-you-sync">What should you sync?</h4>
<p>Due to the purpose of sync as described above, you can only sync classes in Veezoo. But not all classes make sense to sync.</p>
<p>Following the example above, here is what would make sense to sync:</p>
<ol>
<li>
<p><strong>Products</strong>: If new products are being added, you'd want to sync the Product class to reflect these changes. This way, when you ask Veezoo "How many orders of Dresses did we sell last month?", "Dresses" resolves to the right product - even for newly added products.</p>
</li>
<li>
<p><strong>Categories</strong>: If new product categories are being introduced, the Category class should be synced. This lets questions like "How much revenue did we generate from the Clothing category last year?" filter on the right category.</p>
</li>
<li>
<p><strong>(Potentially) Customers</strong>: If you're interested in asking questions related to specific customers, then syncing the Customer class can be useful. This lets a query like "What did John Doe purchase last month?" resolve "John Doe" to the right customer. If there are millions of customers though, Veezoo does not support syncing and you may want to ask using <code>string</code> or the <a href="/vkl/kb-layer/attribute/extends/id/">onto.ID pattern</a>.</p>
</li>
</ol>
<p>Here is what you CANNOT sync or MAY NOT want to sync:</p>
<ol>
<li>
<p><strong>Price</strong>: Since it is not a class, you cannot sync Price. Questions like "What is the total revenue from T-shirts last month?" don't require the Knowledge Graph to know the individual prices. The calculation of revenue happens at the level of the database, not at the level of the Knowledge Graph.</p>
</li>
<li>
<p><strong>Product Description</strong>: The description column is not necessary to sync because users typically don't refer to a product by its description in a question. Syncing is about giving the AI agent and autocomplete the entity values users actually mention. The best practice is also to model Description as a <code>string</code> and not a <code>class</code>.</p>
</li>
<li>
<p><strong>Order Date</strong>: The order_date column cannot be synced because it is not a class - date values don't need to be known as entities.</p>
</li>
<li>
<p><strong>Order ID</strong>: The Orders class is usually not synced, because often users won't care about asking questions about specific Order IDs. Even if they want to do so, you should follow the <a href="/vkl/kb-layer/attribute/extends/id/">onto.ID pattern</a> instead.</p>
</li>
</ol>
<h3 id="how-do-i-run-entity-synchronizations">How do I run entity synchronizations?</h3>
<h4 id="manual-sync">Manual Sync</h4>
<p>By default, Veezoo does not automatically schedule entity synchronizations.</p>
<p>So the most common way to sync is by:</p>
<ol>
<li>Open in Veezoo Studio the file for the class you want to sync (under <code>knowledge-base/classes/...</code>). You can get there quickly by going to the Knowledge Graph sidebar, hovering over the class and clicking to "Open in Studio" in the info panel.</li>
</ol>
<p><img src="/img/kg-sync/open-in-studio.png" alt="Open in Veezoo Studio"></p>
<ol start="2">
<li>You will notice on the top bar of the file a sync icon.</li>
</ol>
<p><img src="/img/kg-sync/sync-button.png" alt="Sync Button"></p>
<ol start="3">
<li>Click on it and select the classes you want to sync.</li>
</ol>
<p><img src="/img/kg-sync/choose-classes.png" alt="Choose Classes"></p>
<ol start="4">
<li>Wait... and that's it.</li>
</ol>
<p><img src="/img/kg-sync/success.png" alt="Success"></p>
<h4 id="scheduled-sync">Scheduled Sync</h4>
<p>If there are always new individual values being added, you may want to schedule your sync to run with a certain frequency.</p>
<ol>
<li>To do this, go to the <a href="https://app.veezoo.com/studio/synchronization">Synchronization view</a> in Studio.</li>
</ol>
<p><img src="/img/kg-sync/synchronization.png" alt="Synchronization"></p>
<ol start="2">
<li>
<p>Click on the <code>+ SCHEDULE</code> button.</p>
</li>
<li>
<p>Select when the sync should start and how frequent (once, every hour, every day, every week).</p>
</li>
</ol>
<p><img src="/img/kg-sync/start_frequency.png" alt="Start and Frequency"></p>
<ol start="4">
<li>Now you can choose which concepts should be synced or whether you want all concepts with an explicit sync policy set to be synced (see next section).</li>
</ol>
<p><img src="/img/kg-sync/concepts.png" alt="Concepts"></p>
<h4 id="scheduled-sync-with-sync-policy">Scheduled Sync with Sync Policy</h4>
<p>To do that, you will need to:</p>
<ol>
<li>
<p>Open Veezoo Studio and open the file for each class you want to schedule the sync.</p>
</li>
<li>
<p>Inside each class you want to sync, add a sync_policy:</p>
<ul>
<li>
<p>If you want to keep changes you may have done to the entities (e.g. synonyms, renaming), add: <code>sync_policy: "merge"</code></p>
</li>
<li>
<p>If you want to always replace the entities with the new ones: <code>sync_policy: "replace"</code></p>
</li>
</ul>
</li>
</ol>

<h2 id="schema-synchronization">Schema Synchronization</h2>
<p>The schema synchronization runs automatically once per day at a fixed hour and performs two key tasks:</p>
<h3 id="1-schema-validation">1. Schema Validation</h3>
<p>Checks whether the schemas, tables, and columns configured in your Knowledge Graph's database layer still match the actual schema of your database. This helps detect issues early, such as:</p>
<ul>
<li>A table that was renamed or deleted</li>
<li>A column that no longer exists</li>
<li>A schema that is no longer accessible</li>
</ul>
<p>If any discrepancies are found, a warning will be displayed in the Synchronization view.</p>
<h3 id="2-metadata-description-updates">2. Metadata Description Updates</h3>
<p>Updates the <a href="/vkl/kb-layer/general/synced_description"><code>synced_description</code></a> property of all classes and attributes. These descriptions are fetched from your database's metadata—depending on your database system, these may be called "comments" or "documentation."</p>
<p>This allows you to maintain documentation in your data warehouse and have it automatically reflected in Veezoo's Knowledge Graph.</p>
<h3 id="differences-from-entity-synchronizations">Differences from Entity Synchronizations</h3>
<p>Unlike entity synchronizations, schema synchronization run at a fixed time and can neither be disabled nor customized.</p>
<p><img src="/img/kg-sync/schema-sync.png" alt="Schema Synchronization Schedule"></p>
<h3 id="viewing-schema-synchronization-runs">Viewing Schema Synchronization Runs</h3>
<p>Schema synchronization runs are displayed in the same table as entity synchronizations in the Synchronization view. If the synchronization detects any missing database objects (schemas, tables, or columns), a warning indicator will be shown. Click the details row to see the missing items.</p>
