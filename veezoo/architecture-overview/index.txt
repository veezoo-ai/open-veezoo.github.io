15:T4d8a,<h2 id="what-is-veezoo">What is Veezoo?</h2>
<p>Veezoo is an Agentic Analytics platform that allows anyone to ask questions in natural language and get precise, trustworthy answers directly from their data warehouse. At the heart of this architecture is the Veezoo Knowledge Graph, which provides the foundation that makes every answer accurate, understandable, and aligned with a company's business logic and permissioning.</p>
<h2 id="the-knowledge-graph">The Knowledge Graph</h2>
<p>The Knowledge Graph serves as a semantic layer that abstracts the data warehouse complexity for business users, incorporating governance and trust. Furthermore, it serves as the contextual foundation that enables the Veezoo AI to understand and respond to user questions accurately.
Companies can have one or multiple knowledge graphs depending on use-case and architectural preferences.
E.g. A company might have Knowledge Graphs for sales, finance, HR and permission them accordingly.</p>
<p><strong>A Knowledge Graph captures</strong>:</p>
<ul>
<li><strong>Business concepts</strong>: Classes (e.g. Customer, Order, Product), their specific entities (e.g. Coca_Cola, Pepsi, Microsoft), and relationships between classes, all mapped to underlying data warehouse tables and columns</li>
<li><strong>Semantic definitions</strong>: Business glossary, concept descriptions, and operational context that align with company terminology and processes</li>
<li><strong>Metrics &#x26; KPIs</strong>: Reusable measure definitions with precise calculation logic (e.g., "Revenue" always excludes returns and taxes)</li>
<li><strong>Governance rules</strong>: Role-based access controls, row-level permissions, and data visibility restrictions</li>
<li><strong>AI behavior guidance</strong>: Instructions for how the AI should approach analysis, interpret questions, respond to users, and what tone of voice to use</li>
<li><strong>Business logic</strong>: Complex calculations, data validation rules, and domain-specific transformations</li>
</ul>
<p>The Knowledge Graph presents a normalized, relationship-rich view of your business concepts regardless of your underlying data warehouse structure. Whether your data warehouse uses a single denormalized table, star schema, or data vault architecture, the Knowledge Graph models intuitive business relationships like "Customer places Order for Product" that users can naturally explore.</p>
<aside class="docs-aside docs-aside--tip" data-title="Modeling Tip"><p class="docs-aside__title">Modeling Tip</p><p>Prefer modeling relationships only at their natural level of granularity. If a clear path already exists, avoid adding redundant direct relationships. For example, prefer Line Item → Order and Order → Store rather than also adding Line Item → Store — unless line items can belong to different stores. This keeps the graph simpler, avoids ambiguity, and ensures consistent results.</p></aside>
<p>The Knowledge Graph is defined in VKL (Veezoo Knowledge Language) and can be queried to get results from the underlying data sources using VQL (Veezoo Query Language). VQL acts as an intermediate language that the AI uses to bridge natural language questions and SQL queries, operating on Knowledge Graph concepts rather than raw database tables.</p>
<p>These layered abstractions — from raw tables to business concepts and reusable measures — let Veezoo answer complex questions using simple, high‑level terms while hiding all technical complexity.</p>
<aside class="docs-aside docs-aside--note" data-title="No Data Copying"><p class="docs-aside__title">No Data Copying</p><p>The Knowledge Graph contains semantic metadata and business logic definitions, not the company's raw transactional data. It provides a semantic layer that maps business concepts to the underlying data warehouse.</p></aside>
<h2 id="how-veezoo-processes-a-question">How Veezoo Processes a Question</h2>
<p>When a user asks a question, Veezoo processes it through a sequence of steps, each involving sophisticated technology working behind the scenes:</p>
<aside class="docs-aside docs-aside--note" data-title="Query Processing Sequence"><p class="docs-aside__title">Query Processing Sequence</p><ol>
<li>
<p><strong>Natural Language Input</strong><br>
A user submits a question in plain language.</p>
</li>
<li>
<p><strong>Semantic Resolution</strong><br>
Veezoo resolves the question against the Knowledge Graph, identifying the relevant classes (Customer, Product), specific entities (Bill_Gates, Coca_Cola, Pepsi), metrics (Revenue), time periods (Q4 2023), and other building blocks.</p>
</li>
<li>
<p><strong>Agentic Plan</strong><br>
Based on the Knowledge Graph, the chat history, and the current question, Veezoo builds an execution plan determining which VQL queries to run and in what order. Simple questions use straightforward plans, while complex analyses may require adaptive plans that adjust based on intermediate results. Along the way, the AI agent can use tools to gather context: searching the Knowledge Graph, reading concept details and notes, and opening your boards and canvases. Most requests are handled by a Base Model; complex tasks are automatically upgraded to an Advanced Model. For long or complex questions, Veezoo shows a task checklist so you can follow its progress.</p>
</li>
<li>
<p><strong>VQL to SQL Compilation</strong><br>
Each VQL step is compiled deterministically into SQL, taking all business logic and governance rules into account.</p>
</li>
<li>
<p><strong>Execution</strong><br>
The SQL runs directly in the customer's data warehouse. No data movement or duplication is required.</p>
</li>
<li>
<p><strong>Verification</strong><br>
Every number the AI quotes from your data is verified character-for-character against the actual query results before it is displayed. Verified numbers are clickable, so you can trace each data point back to its source.</p>
</li>
<li>
<p><strong>Visualization &#x26; Output</strong><br>
The AI may request a chart type, but Veezoo's deterministic chart selector validates the choice and picks the best fit otherwise. Depending on the question, the answer takes different forms: text with charts, whole boards, or interactive <a href="/veezoo/boards-and-canvases/canvases">Canvases</a>.</p>
</li>
</ol></aside>
<aside class="docs-aside docs-aside--caution" data-title="Key Architectural Principle"><p class="docs-aside__title">Key Architectural Principle</p><p><strong>The AI does not write SQL</strong>. The AI only reasons over business concepts in the Knowledge Graph; compilation from VQL to SQL is deterministic and happens without AI involvement. This is why you can't "jailbreak" it into listing raw tables and why Veezoo computes your KPIs accurately every time. Users never interact with the data warehouse directly; they interact with the modeled and exposed business concepts. This separation of concerns ensures KPI definitions are applied exactly as modeled.</p></aside>
<h2 id="frequently-asked-questions">Frequently Asked Questions</h2>
<p>These are some of our most common questions. If yours isn't listed, please reach out to <a href="mailto:support@veezoo.com">support@veezoo.com</a>.</p>
<details>
<summary><strong>"How can we trust AI-generated analytics results? What prevents hallucinations?"</strong></summary>
<p><strong>The concern</strong>: AI tools often generate plausible-sounding but incorrect answers, making them unreliable for business-critical decisions.</p>
<p><strong>Veezoo's approach</strong>: Veezoo's architecture eliminates AI hallucinations through deterministic result generation and abstraction layers:</p>
<ul>
<li><strong>Pre-Defined Business Logic</strong>: The AI operates exclusively on pre-defined business concepts and measures within the Knowledge Graph, preventing results from deviating from established business definitions</li>
<li><strong>Deterministic Computation</strong>: The VQL → SQL pipeline follows rule-based compilation that can be inspected at every step — technical users can examine both the VQL and the generated SQL for complete result traceability</li>
<li><strong>Transparent Dynamic Calculations</strong>: When the AI creates dynamic measures (sums, averages, percentages), it provides clear explanations and uses reusable measure abstractions, maintaining consistency across users and questions. For example, if the graph defines an Order concept, Veezoo can compute "Number of Orders" without a pre‑defined measure and show the exact formula. This balances central governance of core KPIs with decentralized freedom to explore.</li>
<li><strong>Consistent Presentation</strong>: Chart titles, filters, and labels are constructed directly from Knowledge Graph metadata and executed VQL, eliminating dependence on unpredictable language model generation — deterministically rendered from VQL to always match the charts.</li>
</ul>
</details>
<details>
<summary><strong>"How can we make sure that users only see what they are allowed to see?"</strong></summary>
<p><strong>The concern</strong>: Different teams need access to different data sets, and we can't risk unauthorized access to sensitive information.</p>
<p><strong>Veezoo's approach</strong>: Multi-layered security that prevents prompt injection attacks and unauthorized access:</p>
<ul>
<li><strong>Knowledge Graph Level Access</strong>: Control which Knowledge Graphs users can ask questions about based on role. Assign Finance teams to the "Financial Analytics" graph while restricting HR teams to the "People Analytics" graph</li>
<li><strong>Column-Level Security</strong>: Granularly control attribute visibility. Restrict <code>Profit_Margin</code> to only "management" and "finance" roles, or limit PII fields like <code>Customer_SSN</code> to "admin" users only, making sensitive concepts completely invisible to unauthorized users</li>
<li><strong>Row-Level Security</strong>: Implement filtering based on user attributes. C-level executives see data across all customers while account executives only see their own portfolio where <code>account_owner</code> matches their user ID</li>
<li><strong>Prompt Injection Protection</strong>: Because the AI never writes SQL directly and operates only on pre-defined business concepts, users cannot "jailbreak" the system to access unauthorized data</li>
</ul>
</details>
<details>
<summary><strong>"What happens when our database schema changes? Will everything break?"</strong></summary>
<p><strong>The concern</strong>: Schema changes typically break analytics tools and require extensive updates across multiple systems.</p>
<p><strong>Veezoo's approach</strong>: Resilient architecture that adapts to database evolution:</p>
<ul>
<li><strong>Isolated Impact</strong>: When underlying table structures change, only the VKL mappings need updating — dashboards, user queries and business logic remain intact</li>
<li><strong>Continuous Availability</strong>: Business users can continue asking questions while data teams update the semantic mappings behind the scenes</li>
<li><strong>Change Management</strong>: The Knowledge Graph acts as a buffer between business users and technical schema changes, maintaining consistent business definitions even as data structures evolve</li>
<li><strong>Business Continuity</strong>: Users continue working with the same familiar business concepts regardless of technical changes underneath</li>
</ul>
</details>
<details>
<summary><strong>"Do we need to move our data or create additional infrastructure?"</strong></summary>
<p><strong>The concern</strong>: Data movement creates security risks, compliance issues, and additional infrastructure costs.</p>
<p><strong>Veezoo's approach</strong>: Works directly with your existing data warehouse:</p>
<ul>
<li><strong>No Data Duplication</strong>: All processing happens directly in your existing data warehouse — no ETL pipelines to maintain</li>
<li><strong>Real-Time Insights</strong>: Every query returns the most current data from your source systems, ensuring decisions are based on live information</li>
<li><strong>Single Source of Truth</strong>: Users access the same data warehouse that powers your other critical systems, eliminating inconsistencies between analytics tools</li>
<li><strong>Native Processing</strong>: Leverages your warehouse's native compute power and optimizations for maximum performance</li>
</ul>
</details>
<details>
<summary><strong>"How can we audit and validate the results that AI provides?"</strong></summary>
<p><strong>The concern</strong>: We need full transparency and auditability for compliance and trust in business-critical decisions.</p>
<p><strong>Veezoo's approach</strong>: Complete visibility into every step of query processing:</p>
<ul>
<li><strong>VQL Visibility</strong>: Technical Users can inspect the intermediate Veezoo Query Language (VQL) that represents their question</li>
<li><strong>SQL Generation</strong>: View the exact SQL query that Veezoo compiles from VQL, ensuring full auditability of results</li>
<li><strong>Deterministic Pipeline</strong>: The VQL → SQL transformation is rule-based and repeatable, not dependent on unpredictable AI model behavior</li>
</ul>
</details>
<details>
<summary><strong>"Can my data team see what users are asking and how Veezoo is being used?"</strong></summary>
<p><strong>The concern</strong>: We need visibility into adoption, questions, and performance to drive success.</p>
<p><strong>Veezoo's approach</strong>: MetaVeezoo provides transparent monitoring and actionable insights:</p>
<ul>
<li><strong>Usage analytics</strong>: Track logins, number of questions, feedback trends, and adoption over time</li>
<li><strong>Question intelligence</strong>: See asked questions and unrecognized concepts to proactively extend the Knowledge Graph</li>
<li><strong>Experience optimization</strong>: Identify friction, personalize onboarding, and measure content effectiveness</li>
<li><strong>Performance monitoring</strong>: Monitor SQL durations and system behavior to catch issues before users do</li>
<li><strong>Custom dashboards</strong>: Build tailored monitoring boards to focus on the KPIs that matter to your org</li>
</ul>
</details>
<details>
<summary><strong>"Will investing in names, descriptions and context actually improve business adoption and AI accuracy?"</strong></summary>
<p><strong>The concern</strong>: We don't want to spend time documenting concepts if users won't benefit.</p>
<p><strong>Veezoo's approach</strong>: It's a two‑for‑one — the same Knowledge Graph metadata powers both the user experience and the AI's reasoning:</p>
<ul>
<li><strong>Improved Data Literacy</strong>: Users interact with clear business concepts (e.g., Customer, Revenue, Orders) instead of cryptic tables/columns</li>
<li><strong>Consistent Definitions</strong>: KPIs are defined once in the Knowledge Graph and reused everywhere, eliminating multiple versions of truth</li>
<li><strong>AI‑Powered Accuracy</strong>: Richer descriptions, synonyms, and business rules increase answer precision and reduce misunderstandings</li>
<li><strong>Two‑for‑one Documentation</strong>: Descriptions are displayed to users and consumed by the AI to interpret questions correctly</li>
</ul>
</details>
<details>
<summary><strong>"Do we need a specific data model for Veezoo to work (star schema, naming, conventions)?"</strong></summary>
<p><strong>The concern</strong>: We don't want to remodel our warehouse just to adopt Veezoo.</p>
<p><strong>Veezoo's approach</strong>: No redesign required — Veezoo works with a wide range of modeling styles:</p>
<ul>
<li><strong>Flexible modeling</strong>: Supports denormalized flat tables, star/snowflake, data vault, and mixed/legacy models</li>
<li><strong>Name abstraction</strong>: Table and column names can be cryptic; VKL maps clean business concepts to any physical names</li>
<li><strong>Relationship modeling</strong>: The Knowledge Graph expresses business relationships regardless of the underlying physical structure</li>
</ul>
<p><strong>Best practice</strong>: If you can choose, a normalized model is preferable as it will have the lowest complexity and require the least amount of configuration to setup.</p>
</details>
<details>
<summary><strong>"How long does it take to set up, and how easy is it to maintain?"</strong></summary>
<p><strong>The concern</strong>: We need fast time‑to‑value and a low‑overhead way to keep things current.</p>
<p><strong>Veezoo's approach</strong>: Rapid setup and streamlined maintenance:</p>
<ul>
<li><strong>Minutes to first answers</strong>: Once the data warehouse connection is established, Veezoo Studio can auto‑generate your initial Knowledge Graph so teams can start asking questions the same day</li>
<li><strong>Guided modeling UI</strong>: Use Studio to refine names, relationships, measures, and permissions with smart suggestions, previews, and validations</li>
<li><strong>Copilot‑assisted changes</strong>: A powerful Copilot helps implement VKL changes and best practices quickly (e.g., synonyms, defaults, tests) — all trackable in Git</li>
<li><strong>Safe rollout</strong>: Develop in branches and promote changes via reviews and tests without impacting business users</li>
<li><strong>Low operations</strong>: No data movement; deterministic VQL→SQL. Ongoing updates like entity syncs are automated and tweaks are quick and auditable</li>
</ul>
</details>
<details>
<summary><strong>"How does entity awareness improve the user experience and reduce errors?"</strong></summary>
<p><strong>Veezoo models real‑world entities in the Knowledge Graph — not just strings. Entities are the actual distinct values behind your classes</strong> (e.g., "Amazon" as a Customer, "iPhone 15" as a Product), synced/indexed from your warehouse. This brings practical benefits for business users and governance:</p>
<ul>
<li><strong>Context‑Aware Autocomplete</strong>: Suggests valid entities, measures, and relationships as users type, accelerating analysis</li>
<li><strong>Entity Recognition</strong>: Knows which specific customers/products actually exist based on synced entities, avoiding blind string search and mismatches</li>
<li><strong>ID-to-Entity Resolution</strong>: Maps technical IDs (e.g., Customer ID 723) to real entities (e.g., "Acme GmbH"), so users can ask with names or IDs while results and filters remain human-readable</li>
<li><strong>Disambiguation &#x26; Synonyms</strong>: Resolves ambiguous terms and supports business lingo via synonyms so users can ask naturally</li>
<li><strong>Error Prevention</strong>: Prevents invalid queries before execution by validating against known entities and semantics</li>
<li><strong>Consistent Metrics by Entity</strong>: Ensures entity-scoped measures behave consistently across questions and visualizations</li>
</ul>
</details>
<details>
<summary><strong>"Can our data team manage the Knowledge Graph as code and promote changes safely without impacting business users?"</strong></summary>
<p><strong>Yes.</strong> The entire Knowledge Graph is defined as VKL code and stored in a Git-backed repository, so it fits naturally into standard software development workflows:</p>
<ul>
<li><strong>Version control</strong>: Every change to VKL files is tracked, diffable, and auditable</li>
<li><strong>Safe collaboration</strong>: Multiple contributors work on <strong>Git branches</strong> without impacting the live graph; business users continue using the main branch</li>
<li><strong>Code review &#x26; CI</strong>: Review VKL diffs and run validations/tests before merging</li>
<li><strong>Isolated testing</strong>: Use Veezoo's development branches and tests to validate changes against real questions and boards prior to rollout</li>
</ul>
