15:Ta7cd,<p>Veezoo's Embedded Analytics offers an integration solution that enhances your applications with our sophisticated, natural language querying (NLQ) data analytics and visualization capabilities.</p>
<h2 id="about">About</h2>
<h3 id="value-proposition">Value Proposition</h3>
<p>You can integrate Veezoo’s conversational, Self-Service Analytics interface directly into your software or portal. With Embedded Veezoo, you give your users the flexibility to explore the data they want without making your software more complicated nor wasting development resources.</p>
<p>Our robust security, permission, and multi-tenancy architecture ensures that your users or customers only have access to what they’re allowed to see.</p>
<div style="display: flex; justify-content: center">
    <iframe src="https://player.vimeo.com/video/815040762?app_id=122963&#x26;h=8c11281837" width="640" height="360" style="border: 0" allow="autoplay; fullscreen; picture-in-picture" allowfullscreen></iframe>
</div>
<h3 id="characteristics">Characteristics</h3>
<ul>
<li>Seamless integration into your application for an improved user experience.</li>
<li>Supports multi-tenant architectures, providing personalized data experiences.</li>
<li>Utilizes JWT (JSON Web Tokens) for secure user authentication.</li>
</ul>
<h2 id="1-contact-us-to-enable-embedded-analytics">1. Contact Us to Enable Embedded Analytics</h2>
<p>The first step is to <a href="https://www.veezoo.com/contact">contact us</a> if you are interested in the embedded functionality of Veezoo. This feature is not part of the Free tier and comes with a tailored pricing on request.</p>
<h2 id="2-configure-allowed-hosts">2. Configure Allowed Hosts</h2>
<p>On the <em>Embedding Configuration</em> page, make sure the Toggle Switch is ON (Embedding is enabled).</p>
<p>For secure embedding, you need to specify the allowed hosts in Veezoo's admin settings. This ensures that your Veezoo content is only accessible from your designated, trusted domains.</p>
<p><img src="/img/embedded/admin-embedded-config.png" alt="Admin Embedded Configuration"></p>
<h2 id="3-configure-a-public-key-to-setup-jwt-json-web-tokens">3. Configure a Public Key to setup JWT (JSON Web Tokens)</h2>
<p>Veezoo supports <a href="/veezoo/single-sign-on/jwt">JWT</a> for user authentication within Embedded Analytics. To enable secure access to relevant data and analytics, your application will have to generate a JWT on your server and pass it to Veezoo. For that to work, you will need to configure in Veezoo Admin the public key for a private key that will be used by your application to sign the token.</p>
<p>If you don't know how to create a key pair, follow the instructions provided in Veezoo Admin.</p>
<h2 id="4-configure-tenants-in-veezoo">4. Configure Tenants in Veezoo</h2>
<p>Veezoo's Embedded Analytics supports multi-tenant architectures. A tenant corresponds usually to a customer of yours, which may have multiple users in your application. Veezoo needs to know about the existence of these tenants, so that when a user accesses Veezoo through your application it will access the Knowledge Graph with the right authorization logic.</p>
<p>To configure Tenants in Veezoo, go to <a href="https://app.veezoo.com/admin/embedded/tenants">Veezoo Admin > Embedded > Tenants</a>.</p>
<aside class="docs-aside docs-aside--note" data-title="Note"><p class="docs-aside__title">Note</p><p>Currently these need to be manually added over the UI, but we plan to release a Veezoo Admin API to do this programatically.</p></aside>
<p><img src="/img/embedded/admin-embedded-tenants.png" alt="Admin Embedded Tenants"></p>
<p>You will have to give it a name and a Tenant ID, which is the ID your application uses to identify a tenant. This will be important for mapping a user to the right tenant as part of the JWT authentication.</p>
<p><img src="/img/embedded/admin-embedded-create-tenant.png" alt="Admin Embedded Create Tenant"></p>
<h2 id="5-provide-access-to-a-knowledge-graph-for-a-tenant">5. Provide Access to a Knowledge Graph for a Tenant</h2>
<p>Choose the Knowledge Graph that will be available for your tenants and configure Tenant Access in Studio.</p>
<p><img src="/img/embedded/studio-tenant-access.png" alt="Studio > Tenant Access"></p>
<p>Veezoo will generate a different view of the same Knowledge Graph for each tenant. You will still manage only the main Knowledge Graph, but in the next steps you will configure how the authorization logic works for each tenant. This way, users will see different data in their answers and dashboards and different entities in the AutoComplete.</p>
<p><img src="/img/embedded/studio-create-tenant-kg.png" alt="Studio > Tenant Access > Create"></p>
<aside class="docs-aside docs-aside--note" data-title="Note"><p class="docs-aside__title">Note</p><p>Currently these need to be manually added over the UI, but we plan to release a Veezoo Admin API to do this programatically.</p></aside>
<h2 id="6-publish-changes-to-tenants">6. Publish Changes to Tenants</h2>
<p>While you develop your Knowledge Graph further, you will want to eventually publish the changes to your tenants.</p>
<p>To do that, you will have to 'update' them over the UI in <code>Studio > Tenant Access</code>. Select which ones to update (or all) and click on <code>Update</code>.</p>
<p><img src="/img/embedded/studio-update-tenants.png" alt="Studio > Tenant Access > Update"></p>
<h2 id="7-define-authorization-logic-for-tenants">7. Define Authorization Logic for Tenants</h2>
<p>Veezoo supports granular control over data access through variables and row-level permissions. This allows you to define which rows of data within a KG are accessible by a specific tenant.</p>
<h3 id="what-are-variables">What are Variables?</h3>
<p>You can think of variables as placeholders defined in the Knowledge Graph and which can have a different value assigned per tenant. These variables can be used in SQL queries or for the database connection, so you can tell Veezoo how to restrict the data for each tenant.</p>
<aside class="docs-aside docs-aside--note" data-title="Note"><p class="docs-aside__title">Note</p><p>By default, you can already access the content of the variable <code>veezoo.Tenant.Id</code> with the ID you've configured for your tenant in the step 4 above. This is the most common way to do row-level authorization for your tenants. But if you need to create other variables, follow the next steps.</p></aside>
<p>To create variables for your Knowledge Graph, you will have to create a new file of type 'Variable' in Studio.</p>
<p><img src="/img/embedded/studio-create-variables.png" alt="Studio > Files > Variables"></p>
<p><img src="/img/embedded/studio-create-variables-modal.png" alt="Studio > Files > Variables > Modal"></p>
<p>Example content:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#24292E">variable company_id {</span></span>
<span class="line"><span style="color:#24292E">  # Leave blank</span></span>
<span class="line"><span style="color:#24292E">}</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E"># You can also have multiple </span><span style="color:#D73A49">in</span><span style="color:#24292E"> the same file</span></span>

<span class="line"><span style="color:#24292E">  # Leave blank</span></span>
<span class="line"><span style="color:#24292E">}</span></span></code></pre></figure>
<p>If you declare a new variable, you will have to first publish these changes to your tenant views of the Knowledge Graph, before you are able to assign values. Follow the same steps as in the section 'Publish Changes to Tenants' above.</p>
<p>Now you can assign a value to these variables for each tenant, incl. for the main Knowledge Graph, by going on the Tenant Access page and clicking on the pencil at the Variables column.</p>
<p><img src="/img/embedded/studio-edit-variables.png" alt="Studio > Tenant Access > Variables"></p>
<p>Now let's see how we can use these variables to restrict data access.</p>
<h3 id="authorization-over-virtual_table">Authorization over virtual_table</h3>
<p>With <a href="/vkl/db-layer/virtual-table">virtual_table</a> you can define SQL with special templating to specify <a href="/veezoo/authorization/row-level-permission">row-level authorization</a> needed for your tenants. Read the related articles linked to understand more about how to work with it.</p>

<h2 id="8-configure-shared-and-non-shared-entities">8. Configure Shared and Non-Shared Entities</h2>
<p>Once you've configured the authorization logic for the tenants, you will want to check which <a href="/vkl/kb-layer/entity">Entities</a> should be shared / common to all tenants and which ones are tenant-specific.</p>
<p>As an example, let's say you have an HR application with information about the hiring process, where there is a status for it. It could be that <code>Status</code> is a class with entities that are common to all tenants. In this case, you don't have to do anything specifically for it.</p>
<p>But let's say you have another class called <code>Candidate</code>. In this case, each tenant will want to see its own candidates. For that, apart from configuring the authorization logic described in the previous section, you will have to delete the entities of the class <code>Candidate</code> and select it as a class to be synced (cf. <a href="/veezoo/sync/kg-sync">Knowledge Graph Synchronization</a>).</p>
<p>Don't forget to "Update" the tenant Knowledge Graphs as described in step 6.</p>
<h2 id="9-embed-veezoo-into-your-application">9. Embed Veezoo into Your Application</h2>
<p>You can integrate Veezoo into your software by incorporating an iframe that points to Veezoo's domain and uses the generated JWT for user authentication.</p>
<h3 id="json-web-token-jwt">JSON Web Token (JWT)</h3>
<p>To embed Veezoo into your application, you will first need to generate a JSON web token (JWT). This token will then be included in the URL used to load the Veezoo interface into an iframe.</p>
<p>The JWT makes use of the following <strong>claims</strong>:</p>

































































<table><thead><tr><th>Key</th><th>Name</th><th>Required</th><th>Description</th></tr></thead><tbody><tr><td><code>iat</code></td><td>Issued at</td><td>required</td><td>Identifies the time at which the JWT was issued</td></tr><tr><td><code>exp</code></td><td>Expiration time</td><td>required</td><td>Identifies the expiration time on and after which the JWT must not be accepted for processing</td></tr><tr><td><code>jti</code></td><td>JWT ID</td><td>required</td><td>A unique identifier for the JWT to avoid replay attacks</td></tr><tr><td><code>tenantId</code></td><td>Tenant ID</td><td>required</td><td>The ID of the tenant in Veezoo the user belongs to</td></tr><tr><td><code>sub</code></td><td>Subject</td><td>required</td><td>Identifies the subject of the JWT, i.e. the user to be authenticated</td></tr><tr><td><code>email</code></td><td>Email</td><td>required</td><td>The email address of the user</td></tr><tr><td><code>firstName</code></td><td>First Name</td><td>required</td><td>The first name of the user</td></tr><tr><td><code>lastName</code></td><td>Last Name</td><td>required</td><td>The last name of the user</td></tr><tr><td><code>language</code></td><td>Language</td><td>optional</td><td>The default language of the user, specified as a <a href="https://en.wikipedia.org/wiki/IETF_language_tag">BCP 47 language tag</a> (currently supported are <code>en-US</code>, <code>de-DE</code>, <code>es-ES</code>, <code>fr-FR</code>, <code>it-IT</code> and <code>pt-BR</code>).</td></tr></tbody></table>
<p>The JWT needs to be <strong>signed</strong> with the <strong>RSA private key</strong> from the public/private key pair of which you have configured the public key in Veezoo Admin.</p>
<h3 id="iframe">iFrame</h3>
<p>To embed Veezoo in your application, you will need to include an iframe in your application's HTML code. The iframe must point to Veezoo using your subdomain and include the JWT in the URL:</p>

<h3 id="testing-your-embedded-integration">Testing Your Embedded Integration</h3>
<p>When testing your embedded Veezoo integration, there are several important considerations to ensure a smooth testing experience:</p>
<h4 id="browser-compatibility-and-third-party-cookies">Browser Compatibility and Third-Party Cookies</h4>
<p>Embedded Veezoo authenticates the iframe using cookies. Because the iframe is loaded in a third-party context relative to the top-level page (your application), browsers treat these as third-party cookies. Veezoo additionally sets <a href="https://developer.mozilla.org/en-US/docs/Web/Privacy/Guides/Privacy_sandbox/Partitioned_cookies">partitioned cookies (CHIPS)</a>, which browsers accept even when they block third-party cookies. This results in the following browser support:</p>
<ul>
<li><strong>Chrome and Edge 114+</strong>: fully supported, including Incognito mode and the "Block third-party cookies" setting.</li>
<li><strong>Firefox 131+</strong>: fully supported.</li>
<li><strong>Safari 18.4 and 26.2 or newer</strong>: fully supported. Note: Apple temporarily disabled partitioned cookies in Safari 18.5 - 26.1; on these versions (and on versions older than 18.4), embedded Veezoo requires third-party cookies to be enabled, which Safari blocks by default.</li>
<li><strong>Older browsers</strong>: require third-party cookies to be enabled in the browser settings.</li>
</ul>
<h4 id="authentication-conflicts">Authentication Conflicts</h4>
<p>If you're logged into Veezoo in the same browser session where you're testing JWT authentication, this can cause authentication conflicts and unexpected behavior.</p>
<h4 id="recommended-testing-setup">Recommended Testing Setup</h4>
<p>To avoid these issues, we recommend using <strong>separate browser profiles</strong> for testing.</p>
<p><strong>Chrome Example:</strong></p>
<ol>
<li>Create a new Chrome profile specifically for testing embedded Veezoo</li>
<li>Do not log into Veezoo directly in this profile - only test the embedding</li>
<li>Use your regular browser profile for normal access to Veezoo</li>
</ol>
