15:Te06,<p>The following guide shows how to configure Veezoo to connect to MongoDB Atlas.</p>
<p>Veezoo connects to MongoDB through the <a href="https://www.mongodb.com/docs/atlas/data-federation/query/sql/">Atlas SQL Interface</a>,
which exposes your collections as SQL tables via an Atlas Data Federation instance. This requires a
MongoDB <strong>Atlas</strong> cluster — self-hosted MongoDB is not supported.</p>
<h2 id="prerequisite-enable-the-atlas-sql-interface">Prerequisite: enable the Atlas SQL Interface</h2>
<ol>
<li>In the Atlas UI, go to <code>Data Federation</code> and create a Federated Database Instance (or use the
<code>Enable Atlas SQL</code> quick-start, which creates one for you).</li>
<li>Add the clusters, databases and collections you want to query to the federated database.</li>
<li>On the federated instance, click <code>Connect</code>, choose <code>Atlas SQL</code>, and select <code>JDBC</code>. Copy the
hostname from the connection string — it looks like
<code>atlas-sql-1234abcd5678efgh-a1bcd.a.query.mongodb.net</code>.</li>
</ol>
<h2 id="creating-a-database-user">Creating a database user</h2>
<p>Create a database user for Veezoo under <code>Database Access</code> in the Atlas UI. Read-only access is
sufficient: the Atlas SQL Interface is read-only by design.</p>
<p>Make sure Veezoo's IP address is allowed under <code>Network Access</code>.</p>
<h2 id="configuring-the-connection-in-veezoo">Configuring the connection in Veezoo</h2>
<p>In the Veezoo database connection form, select <code>MongoDB Atlas</code> and fill in:</p>
<ul>
<li><strong>Atlas SQL Host</strong>: the hostname copied from the JDBC connection string.</li>
<li><strong>Port</strong>: <code>27017</code> (default).</li>
<li><strong>Username</strong> / <strong>Password</strong>: the database user created above.</li>
<li><strong>Federated Database</strong>: the name of the virtual database in your federated instance.</li>
</ul>
<h2 id="schema-management-polymorphism-and-arrays">Schema management, polymorphism and arrays</h2>
<p>The Atlas SQL Interface infers a SQL schema for each collection from a sample of the documents:</p>
<ul>
<li><strong>Polymorphic fields</strong> (fields whose type varies across documents, e.g. sometimes a string and
sometimes a date) are projected as their dominant type. Querying such a field can fail at runtime
on the rows holding another type. If possible, clean up the data, or pin the field's type with the
<a href="https://www.mongodb.com/docs/atlas/data-federation/query/sql/schema-management/"><code>sqlSetSchema</code></a>
command in <code>mongosh</code>.</li>
<li><strong>Nested documents and arrays</strong> are exposed as complex columns that Veezoo does not import. To
query nested data, flatten it into views in your federated database, or pin a flattened schema
via <code>sqlSetSchema</code>.</li>
<li>If the inferred schema becomes stale after the data changes shape, regenerate it with
<a href="https://www.mongodb.com/docs/atlas/data-federation/query/sql/schema-management/"><code>sqlGenerateSchema</code></a>.</li>
</ul>
<h2 id="supported-and-unsupported-features">Supported and unsupported features</h2>
<p>Most Veezoo features work as usual. Known limitations of the Atlas SQL dialect:</p>
<ul>
<li><strong>Window functions</strong> are not supported. Questions that need them (e.g. grouped Top-N) are answered
through Veezoo's built-in post-processing instead, which can be slower on large results.</li>
<li><strong>Median</strong> is computed through post-processing as well, since Atlas SQL has no median aggregate.</li>
