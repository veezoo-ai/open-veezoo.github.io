15:Tbe5a,<h2 id="definition">Definition</h2>
<p>A <code>measure</code> is a computed numeric aggregation, which you would want to refer to in questions directly or in other measure definitions.</p>
<iframe width="800" height="500" src="https://www.youtube.com/embed/gPRsWEJFmQM?si=3Ro-w9S_m6BPxFzk" title="YouTube video player" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" allowfullscreen></iframe>
<h2 id="usage">Usage</h2>
<p>A <code>measure</code> is usually defined inside a top-level class (e.g. Order) and has the following properties:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#24292E">kb {</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">    class</span><span style="color:#6F42C1"> Order</span><span style="color:#24292E"> {</span></span>
<span class="line"><span style="color:#D73A49">        ...</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">        measure Revenue {</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6A737D">            /** The name of the measure so you can refer to it in questions.</span></span>
<span class="line"><span style="color:#6A737D">             *  If this measure is just an intermediate definition, which should not be used in questions, use display_name instead. */</span><span style="color:#24292E"> </span></span>
<span class="line"><span style="color:#24292E">            name.en: </span><span style="color:#032F62">"Revenue"</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6A737D">            /** The return type of the measure. Currently, it can be either a number (or sometimes more specifically an integer). */</span></span>
<span class="line"><span style="color:#D73A49">            return</span><span style="color:#24292E">: number</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6A737D">            /** The definition of the measure. This is written in VQL (Veezoo Query Language), which is our optimized syntax to define measures. */</span></span>
<span class="line"><span style="color:#6F42C1">            definition</span><span style="color:#24292E">:</span></span>
<span class="line"><span style="color:#032F62">                """</span></span>
<span class="line"><span style="color:#032F62">                sum(this.Order_Amount</span><span style="color:#B31D28;font-style:italic">)</span></span>
<span class="line"><span style="color:#032F62">                """</span></span>
<span class="line"><span style="color:#B31D28;font-style:italic">        }</span></span>
<span class="line"><span style="color:#24292E">    }</span></span>
<span class="line"><span style="color:#24292E">}</span></span></code></pre></figure>
<p>A measure can additionally carry a <a href="/vkl/kb-layer/general/description/">description</a> explaining its logic to users, and a <a href="/vkl/kb-layer/attribute/unit/">unit</a> (e.g. <code>unit: onto.Percentage</code> - remember to multiply by 100 in the definition when the result should read as a percentage).</p>
<aside class="docs-aside docs-aside--caution" data-title="Caution"><p class="docs-aside__title">Caution</p><p>When using triple quotes, the opening and closing <code>"""</code> must each be on their own line, as in the examples on this page. Writing <code>definition: """ ... """</code> on a single line is a syntax error that is only reported when you save. See <a href="/vkl/language-reference/#strings">multi-line strings</a> for the full rules.</p></aside>
<p>Let's go over some examples to understand how to use measures in Veezoo.</p>
<h2 id="examples">Examples</h2>
<h3 id="basic-measures">Basic Measures</h3>
<p>First of all, in Veezoo, unlike in other BI tools, you don't need to define a measure to be able to ask questions involving aggregations.
For instance, you don't need to have an "average order amount" explicitly defined to be able to ask about it, since Veezoo knows what average means. This also applies to totals (e.g. total order amount), counts (e.g. number of users) and even percentages (e.g. percentage of First Class orders).</p>
<p>However, sometimes you will still want to define explicitly the measure. The main case we see in Veezoo is when the name of the measure doesn't capture completely the logic behind it.
You may also want to add a description to it and display it more prominently in Autocomplete to guide users better.</p>
<p>Let's start with simple examples:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#24292E">kb {</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">    class</span><span style="color:#6F42C1"> Order</span><span style="color:#24292E"> {</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">        ...</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6A737D">        /** A numeric value defined in the database. */</span></span>
<span class="line"><span style="color:#24292E">        number Order_Amount {</span></span>
<span class="line"><span style="color:#D73A49">            ...</span></span>
<span class="line"><span style="color:#24292E">        }</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">        measure Revenue {</span></span>
<span class="line"><span style="color:#24292E">            name.en: </span><span style="color:#032F62">"Revenue"</span></span>
<span class="line"><span style="color:#D73A49">            return</span><span style="color:#24292E">: number</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">            definition</span><span style="color:#24292E">:</span></span>
<span class="line"><span style="color:#032F62">                """</span></span>
<span class="line"><span style="color:#032F62">                sum(this.Order_Amount</span><span style="color:#B31D28;font-style:italic">)</span></span>
<span class="line"><span style="color:#032F62">                """</span></span>
<span class="line"><span style="color:#B31D28;font-style:italic">        }</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">        measure Avg_Order_Value {</span></span>
<span class="line"><span style="color:#24292E">            name.en: </span><span style="color:#032F62">"Average Order Value"</span></span>
<span class="line"><span style="color:#D73A49">            return</span><span style="color:#24292E">: number</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">            definition</span><span style="color:#24292E">:</span></span>
<span class="line"><span style="color:#032F62">                """</span></span>
<span class="line"><span style="color:#032F62">                average(this.Order_Amount</span><span style="color:#B31D28;font-style:italic">)</span></span>
<span class="line"><span style="color:#032F62">                """</span></span>
<span class="line"><span style="color:#B31D28;font-style:italic">        }</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">        measure Number_of_Orders { </span></span>
<span class="line"><span style="color:#24292E">            name.en: </span><span style="color:#032F62">"Number of Orders"</span></span>
<span class="line"><span style="color:#D73A49">            return</span><span style="color:#24292E">: integer</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">            definition</span><span style="color:#24292E">:</span></span>
<span class="line"><span style="color:#032F62">                """</span></span>
<span class="line"><span style="color:#032F62">                count(this</span><span style="color:#B31D28;font-style:italic">)</span></span>
<span class="line"><span style="color:#032F62">                """</span></span>
<span class="line"><span style="color:#032F62">        }</span><span style="color:#B31D28;font-style:italic"> </span></span>
<span class="line"><span style="color:#24292E">    }</span></span>
<span class="line"><span style="color:#24292E">}</span></span></code></pre></figure>
<p>Measures are defined in VQL. A detailed explanation of this language can be found <a href="/vkl/kb-layer/vql/">here</a>.</p>
<p>The first thing you notice is the usage of the word <code>this</code>. It refers to the top-level class this measure is based on, in this case: <code>kb.Order</code>.</p>
<h3 id="measures-with-filters">Measures with Filters</h3>
<p>As mentioned before, a common case for measures is when there is a non-obvious logic to it, meaning it is not in the name of the measure itself. "Revenue in Germany" for instance does not need to be defined as a measure if Germany is just a country in the database. But maybe "Revenue" itself would require a flag 'is_cancelled' to be false or another filter to be set.</p>
<h4 id="boolean-filters">Boolean filters</h4>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#24292E">kb {</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">    class</span><span style="color:#6F42C1"> Order</span><span style="color:#24292E"> {</span></span>
<span class="line"><span style="color:#D73A49">        ...</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">        number Order_Amount { </span><span style="color:#D73A49">...</span><span style="color:#24292E"> }</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">        boolean is_Cancelled { </span><span style="color:#D73A49">...</span><span style="color:#24292E"> }</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">        measure Revenue {</span></span>
<span class="line"><span style="color:#24292E">            name.en: </span><span style="color:#032F62">"Revenue"</span></span>
<span class="line"><span style="color:#24292E">            </span></span>
<span class="line"><span style="color:#24292E">            description.en: </span><span style="color:#032F62">"Revenue only includes orders that were not cancelled"</span></span>
<span class="line"></span>

<span class="line"></span>

<span class="line"><span style="color:#032F62">                """</span></span>
<span class="line"><span style="color:#032F62">                this.is_Cancelled = fals</span><span style="color:#B31D28;font-style:italic">e</span></span>

<p>Alternatively, if the boolean filter needs to be true, we would have had <code>this.is_Active = true</code>.</p>
<h4 id="entity-filters">Entity filters</h4>
<p>What if we didn't have a boolean flag, but rather a specific entity (e.g. 'Active') that we needed to filter for?</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#24292E">kb {</span></span>

<h4 id="numeric-filters">Numeric filters</h4>
<p>Let's say instead that to calculate Revenue, we should ignore all orders with negative Order_Amount.</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#6F42C1">definition</span><span style="color:#24292E">:</span></span>

<h3 id="compositional-measures">Compositional Measures</h3>
<p>Sometimes we will want to reuse existing measures in new definitions, because we depend on them or because we want to keep the code more readable.</p>
<p>Let's say we want to define gross profit margin in %. We will start by defining it in one measure.</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#24292E">kb {</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">    class</span><span style="color:#6F42C1"> Order</span><span style="color:#24292E"> {</span></span>
<span class="line"><span style="color:#D73A49">        ...</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">        number Gross_Profit_Margin { </span><span style="color:#D73A49">...</span><span style="color:#24292E"> }</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">        number Sale_Price { </span><span style="color:#D73A49">...</span><span style="color:#24292E"> }</span></span>
<span class="line"><span style="color:#24292E">        </span></span>
<span class="line"><span style="color:#24292E">        measure Gross_Profit_Margin_Percentage {</span></span>
<span class="line"><span style="color:#24292E">            name.en: </span><span style="color:#032F62">"Gross Profit Margin (in %)"</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">            return</span><span style="color:#24292E">: number</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">            # So we can see </span><span style="color:#D73A49">in</span><span style="color:#D73A49"> %</span></span>
<span class="line"><span style="color:#6F42C1">            unit</span><span style="color:#24292E">: onto.Percentage</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">            definition</span><span style="color:#24292E">:</span></span>
<span class="line"><span style="color:#032F62">                """</span></span>
<span class="line"><span style="color:#032F62">                var total_gpm = sum(this.Gross_Profit_Margin</span><span style="color:#B31D28;font-style:italic">)</span></span>
<span class="line"><span style="color:#D73A49">                var</span><span style="color:#24292E"> total_sale </span><span style="color:#D73A49">=</span><span style="color:#6F42C1"> sum</span><span style="color:#24292E">(</span><span style="color:#005CC5">this</span><span style="color:#24292E">.Sale_Price)</span></span>

<span class="line"><span style="color:#032F62">                """</span></span>
<span class="line"><span style="color:#B31D28;font-style:italic">        }</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">    }</span></span>

<p>Great. But this assumes that gross profit margin and sale price just require a sum. As we have seen before, these could be arbitrarily complex.</p>
<p>So let's say we have two measures <code>Total_Gross_Profit_Margin</code> and <code>Total_Sale_Price</code>. And now we will define it again using these measures.</p>

<p>The syntax to refer to a measure is similar to an aggregation function (e.g. sum, count), meaning it takes an argument. The argument is usually <code>this</code>, which is the top-level class with all the filters from the question.</p>
<h3 id="ratio-measures">Ratio Measures</h3>
<p>Consider the following situation: You have a class <code>Newsletter</code> which has the Booleans <code>opened</code> and <code>clicked</code>. You now want to define the CTR (click through-rate), computed as the number of newsletters which are clicked, divided by the number of newsletters which are opened. With a simple measure one might (wrongly) try the following:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#6F42C1">definition</span><span style="color:#24292E">:</span></span>
<span class="line"><span style="color:#032F62">    """</span></span>
<span class="line"><span style="color:#032F62">    var openedNewsletters = thi</span><span style="color:#B31D28;font-style:italic">s</span></span>
<span class="line"><span style="color:#D73A49">    var</span><span style="color:#24292E"> clickedNewsletters </span><span style="color:#D73A49">=</span><span style="color:#005CC5"> this</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">    openedNewsletters.opened </span><span style="color:#D73A49">=</span><span style="color:#005CC5"> true</span></span>
<span class="line"><span style="color:#24292E">    clickedNewsletters.clicked </span><span style="color:#D73A49">=</span><span style="color:#005CC5"> true</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">    count</span><span style="color:#24292E">(clickedNewsletters) </span><span style="color:#D73A49">/</span><span style="color:#6F42C1"> count</span><span style="color:#24292E">(openedNewsletters)</span></span>
<span class="line"><span style="color:#032F62">    """</span></span></code></pre></figure>
<p>Unfortunately this doesn't work. The issue here is that <code>this</code> refers to one specific instance of the class <code>Newsletter</code>, meaning that <code>openedNewsletter</code> and <code>clickedNewsletter</code> refer to the same thing and so when the filters are applied, they are applied to both. This measure would always return 1.</p>
<p>The solution is to use define the ratio measure through other measures:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#24292E">measure </span><span style="color:#005CC5">CTR</span><span style="color:#24292E"> {</span></span>
<span class="line"><span style="color:#6F42C1">    name</span><span style="color:#24292E">: </span><span style="color:#032F62">"click through rate"</span></span>
<span class="line"><span style="color:#24292E">    </span></span>
<span class="line"><span style="color:#6F42C1">    definition</span><span style="color:#24292E">:</span></span>
<span class="line"><span style="color:#032F62">        """</span></span>
<span class="line"><span style="color:#032F62">        kb.Newsletter.clickedLetters(this) / kb.Newsletter.openedLetters(this</span><span style="color:#B31D28;font-style:italic">)</span></span>
<span class="line"><span style="color:#032F62">        """</span></span>
<span class="line"><span style="color:#032F62">    return: numbe</span><span style="color:#B31D28;font-style:italic">r</span></span>
<span class="line"><span style="color:#24292E">}</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">measure openedLetters {</span></span>
<span class="line"><span style="color:#6F42C1">    name</span><span style="color:#24292E">: </span><span style="color:#032F62">"opened Letters"</span></span>
<span class="line"><span style="color:#6F42C1">    hidden</span><span style="color:#24292E">: </span><span style="color:#005CC5">true</span></span>
<span class="line"><span style="color:#24292E">    </span></span>
<span class="line"><span style="color:#6F42C1">    definition</span><span style="color:#24292E">:</span></span>
<span class="line"><span style="color:#032F62">        """</span></span>
<span class="line"><span style="color:#032F62">        this.opened = tru</span><span style="color:#B31D28;font-style:italic">e</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">        count</span><span style="color:#24292E">(</span><span style="color:#005CC5">this</span><span style="color:#24292E">)</span></span>
<span class="line"><span style="color:#032F62">        """</span></span>
<span class="line"><span style="color:#032F62">    return: numbe</span><span style="color:#B31D28;font-style:italic">r</span></span>
<span class="line"><span style="color:#24292E">}</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">measure clickedLetters {</span></span>
<span class="line"><span style="color:#6F42C1">    name</span><span style="color:#24292E">: </span><span style="color:#032F62">"clicked Letters"</span></span>
<span class="line"><span style="color:#6F42C1">    hidden</span><span style="color:#24292E">: </span><span style="color:#005CC5">true</span></span>
<span class="line"><span style="color:#24292E">    </span></span>
<span class="line"><span style="color:#6F42C1">    definition</span><span style="color:#24292E">:</span></span>
<span class="line"><span style="color:#032F62">        """</span></span>
<span class="line"><span style="color:#032F62">        this.clicked = tru</span><span style="color:#B31D28;font-style:italic">e</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">        count</span><span style="color:#24292E">(</span><span style="color:#005CC5">this</span><span style="color:#24292E">)</span></span>
<span class="line"><span style="color:#032F62">        """</span></span>
<span class="line"><span style="color:#032F62">    return: numbe</span><span style="color:#B31D28;font-style:italic">r</span></span>
<span class="line"><span style="color:#24292E">}</span></span></code></pre></figure>
<p>Veezoo makes sure in this case that the calculation of each measure does not affect the other.</p>
<p>Note the <code>hidden: true</code> on the two helper measures: it marks a measure that only exists as a building block for other measures and is not meant to be asked for directly, so it stays out of autocomplete and answers.</p>
<h4 id="net-promoter-score-nps">Net Promoter Score (NPS)</h4>
<p>A common example of a composite measure is the Net Promoter Score (NPS). The NPS is a market research metric based on a single survey question that asks respondents to rate the likelihood of recommending a company, product, or service to a friend or colleague. Respondents are asked to grade what is being surveyed on a scale from 1 to 10, indicating how much they like it. Users are then grouped into three categories: people answering 1–6 are considered detractors, 7–8 passives, and 9–10 promoters.</p>
<p>The NPS is then calculated as the percentage of promoters minus the number of detractors.</p>
<p>Here is how this would be implemented in Veezoo:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#24292E">kb {</span></span>
<span class="line"><span style="color:#D73A49">    class</span><span style="color:#6F42C1"> Feedback</span><span style="color:#24292E"> {</span></span>
<span class="line"><span style="color:#E36209">        name</span><span style="color:#D73A49">:</span><span style="color:#032F62"> "Feedback"</span></span>
<span class="line"><span style="color:#E36209">        sql</span><span style="color:#D73A49">:</span><span style="color:#032F62"> "${Feedback.Id}"</span></span>
<span class="line"><span style="color:#24292E">        </span></span>
<span class="line"><span style="color:#24292E">        number Value {</span></span>
<span class="line"><span style="color:#6F42C1">            name</span><span style="color:#24292E">: </span><span style="color:#032F62">"Value"</span></span>
<span class="line"><span style="color:#24292E">            </span></span>
<span class="line"><span style="color:#6F42C1">            sql</span><span style="color:#24292E">: </span><span style="color:#032F62">"${Feedback.Value}"</span></span>
<span class="line"><span style="color:#24292E">        }</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">        measure PercentageDetractors {</span></span>
<span class="line"><span style="color:#6F42C1">            name</span><span style="color:#24292E">: </span><span style="color:#032F62">"Percentage of Detractors"</span></span>
<span class="line"><span style="color:#24292E">            </span></span>
<span class="line"><span style="color:#6F42C1">            definition</span><span style="color:#24292E">:</span></span>
<span class="line"><span style="color:#032F62">                """</span></span>
<span class="line"><span style="color:#032F62">                var detractors = proportion(this) {</span><span style="color:#B31D28;font-style:italic"> </span></span>

<h3 id="measures-with-multiple-arguments">Measures with Multiple Arguments</h3>
<p>As previously discussed, measures usually take as its argument the class that it is implemented in (which is then referred to as it <code>this</code>). Veezoo supports a more general case of measures as well.</p>
<p>By using the syntax <code>arguments: [kb.Order, kb.Customer, ...]</code>, you can define any number of arguments for the measure. These arguments are then accessible via the keywords <code>arg1</code>, <code>arg2</code>, etc., in the order they appear in the array.</p>
<p>This approach is particularly useful for performing calculations involving multiple, unrelated classes. For example, consider calculating the <code>Loss Ratio</code> for an insurance company. The <code>Loss Ratio</code> could be defined as the total amount paid on <code>Claims</code> divided by the total premiums earned on <code>Policies</code>.</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#24292E">measure Loss_Ratio {</span></span>
<span class="line"><span style="color:#24292E">    name.en: </span><span style="color:#032F62">"Loss Ratio"</span></span>
<span class="line"><span style="color:#24292E">    </span></span>
<span class="line"><span style="color:#6F42C1">    arguments</span><span style="color:#24292E">: [ kb.Claim, kb.Policy ]</span></span>
<span class="line"><span style="color:#6F42C1">    definition</span><span style="color:#24292E">:</span></span>
<span class="line"><span style="color:#032F62">        """</span></span>
<span class="line"><span style="color:#032F62">        sum(arg1.claimAmount) / sum(arg2.premiumAmount</span><span style="color:#B31D28;font-style:italic">)</span></span>
<span class="line"><span style="color:#032F62">        """</span></span>
<span class="line"><span style="color:#032F62">    return: numbe</span><span style="color:#B31D28;font-style:italic">r</span></span>
<span class="line"><span style="color:#24292E">}</span></span></code></pre></figure>
<p>In this scenario, it is necessary to use two arguments. If there were a relationship between <code>Claim</code> and <code>Policy</code>, one might be tempted to define a single-argument measure within <code>kb.Claim</code> as follows:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#24292E">measure Loss_Ratio {</span></span>
<span class="line"><span style="color:#24292E">    name.en: </span><span style="color:#032F62">"Loss Ratio"</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">    definition</span><span style="color:#24292E">:</span></span>
<span class="line"><span style="color:#032F62">        """</span></span>
<span class="line"><span style="color:#032F62">        var policy = this.Polic</span><span style="color:#B31D28;font-style:italic">y</span></span>
<span class="line"><span style="color:#6F42C1">        sum</span><span style="color:#24292E">(</span><span style="color:#005CC5">this</span><span style="color:#24292E">.claimAmount) </span><span style="color:#D73A49">/</span><span style="color:#6F42C1"> sum</span><span style="color:#24292E">(policy.premiumAmount)</span></span>
<span class="line"><span style="color:#032F62">        """</span></span>
<span class="line"><span style="color:#032F62">    return: numbe</span><span style="color:#B31D28;font-style:italic">r</span></span>
<span class="line"><span style="color:#24292E">}</span></span></code></pre></figure>
<p>However, this approach would NOT work because it would filter out all <code>Policies</code> that do not have an associated <code>Claim</code>.
