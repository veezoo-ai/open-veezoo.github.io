15:T59a4,<h2 id="definition">Definition</h2>
<p>The <code>sql</code> property (and related ones) specifies how the class is represented in the database (as a table or a column), what a unique key (<code>sql</code>) for this class is and how its <a href="/vkl/kb-layer/entity">entities</a> are generated from SQL, if it should have any.</p>
<h2 id="usage">Usage</h2>
<p>A class can be defined by a table, a column or a SQL. Let's take the example of a table <code>customer(id, name, status)</code>.</p>
<p>In this example, Veezoo will generate two classes: <code>kb.Customer</code> and <code>kb.Customer.Status</code>.</p>
<h3 id="class-defined-by-table">Class defined by Table</h3>
<p>In the case of <code>kb.Customer</code>, we have a class defined by a table <code>customer</code>.</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">import</span><span style="color:#24292E"> db.postgres.movie_db.public.customer</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">kb {</span></span>
<span class="line"><span style="color:#24292E">    class Customer {</span></span>
<span class="line"><span style="color:#24292E">        name.en: </span><span style="color:#032F62">"Customer"</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">        from_table: customer</span></span>
<span class="line"><span style="color:#6A737D">        // e.g. 00042</span></span>
<span class="line"><span style="color:#24292E">        sql: </span><span style="color:#032F62">"${customer.id}"</span></span>
<span class="line"><span style="color:#6A737D">        // e.g. [00042] Arthur Dent</span></span>
<span class="line"><span style="color:#24292E">        name_sql.en: </span><span style="color:#032F62">"'[' || ${customer.id} || '] ' || ${customer.name}"</span></span>
<span class="line"><span style="color:#6A737D">        // e.g. Arthur Dent</span></span>
<span class="line"><span style="color:#24292E">        synonym_sql.en: </span><span style="color:#032F62">"${customer.name}"</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">        ...</span></span>
<span class="line"><span style="color:#24292E">    }</span></span>
<span class="line"><span style="color:#24292E">}</span></span></code></pre></figure>
<p>Table Classes need to have</p>
<ul>
<li>a reference to the table <code>from_table: customer</code> and</li>
<li>a SQL expression that uniquely identifies it <code>sql: "${customer.id}"</code>, used for Joins as a key.</li>
</ul>
<p>Optionally, if it is a class with values that you may want to refer to in questions (e.g. a specific customer), it makes sense to define the name for the entities of this class.</p>
<p>To do this you will add a <code>name_sql</code>, specifying how the <a href="/vkl/kb-layer/general/name">name</a> of the entity will be generated. It can be written without a language tag when the label is the same for all languages, or with a language tag (e.g. <code>name_sql.en</code> for English) when labels differ per language. If no <code>name_sql</code> is defined, Veezoo will use the <code>sql</code> as the default <code>name_sql</code> expression.</p>
<p>There may be <a href="/vkl/kb-layer/general/synonym">synonyms</a> in the table that you also want to use for the entities. These you will define using the property <code>synonym_sql</code> with the appropriate language tag.
In our example, after clicking on the <code>Sync Entities</code> button in the Editor when you have the class file open, you will get entities like this:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#24292E">kb.Customer {</span></span>
<span class="line"><span style="color:#24292E">    entity 00042_Arthur_Dent_1234 {</span></span>
<span class="line"><span style="color:#24292E">        name.en: </span><span style="color:#032F62">"[00042] Arthur Dent"</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">        synonym.en: </span><span style="color:#032F62">"Arthur Dent"</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">        id</span><span style="color:#24292E">: </span><span style="color:#032F62">"00042"</span></span>
<span class="line"><span style="color:#24292E">    }</span></span>
<span class="line"><span style="color:#D73A49">    ...</span></span>
<span class="line"><span style="color:#24292E">}</span></span>
<span class="line"></span></code></pre></figure>
<p>In the case of a class called <code>kb.Order</code>, you may prefer not to have any entities defined. This means <code>name_sql</code> and <code>synonym_sql</code> will be left out.</p>
<h3 id="class-defined-by-column">Class defined by Column</h3>
<p>In our example, the class <code>kb.Status</code> was defined by the column <code>status</code> in the <code>customer</code> table. Let's take a look at how it would be defined in VKL.</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">import</span><span style="color:#24292E"> db.postgres.movie_db.public.customer</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">kb {</span></span>
<span class="line"><span style="color:#6A737D">    // inside the file for the class Customer</span></span>
<span class="line"><span style="color:#24292E">    class Customer {</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">        ...</span></span>
<span class="line"></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">        class Status {</span></span>
<span class="line"><span style="color:#24292E">            name.en: </span><span style="color:#032F62">"Status"</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6A737D">            // e.g. ACTIVE</span></span>
<span class="line"><span style="color:#24292E">            sql: </span><span style="color:#032F62">"${customer.status}"</span></span>
<span class="line"><span style="color:#24292E">        }</span></span>
<span class="line"><span style="color:#24292E">    }</span></span>
<span class="line"><span style="color:#24292E">}</span></span></code></pre></figure>
<p>Each entity of the class <code>kb.Customer.Status</code> is uniquely defined by the <code>sql</code> expression, which also happens to be the default <code>name_sql</code> for the entities.
In this case, there is no <code>synonym_sql</code> defined.</p>
<aside class="docs-aside docs-aside--caution" data-title="The sql is the class&#x27;s identity"><p class="docs-aside__title">The sql is the class's identity</p><p>Rows with the same <code>sql</code> value become the <strong>same</strong> entity. When raw values can collide, this merges things that should stay apart - e.g. a <code>City</code> class keyed on the raw city name silently adds up every "Springfield" across states into one clean-looking number. Fix it by making the <code>sql</code> unique and keeping the label human with <code>name_sql</code>:</p><figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">class</span><span style="color:#6F42C1"> City</span><span style="color:#24292E"> {</span></span>
<span class="line"><span style="color:#24292E">    name.en</span><span style="color:#D73A49">:</span><span style="color:#032F62"> "City"</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6A737D">    // identity: each real city is its own entity</span></span>
<span class="line"><span style="color:#E36209">    sql</span><span style="color:#D73A49">:</span><span style="color:#032F62"> "${ORDERS.city} || ', ' || ${ORDERS.state}"</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6A737D">    // label: "Springfield (Ohio)"</span></span>
<span class="line"><span style="color:#24292E">    name_sql.en</span><span style="color:#D73A49">:</span><span style="color:#032F62"> "${ORDERS.city} || ' (' || ${ORDERS.state} || ')'"</span></span>
<span class="line"><span style="color:#24292E">}</span></span></code></pre></figure></aside>
<h3 id="advanced-class-defined-by-table-sql">Advanced: Class defined by Table SQL</h3>
<p>Let's assume that the <code>customer</code> table is split across two tables <code>corporate_customer</code> and <code>private_customer</code>, both with the same set of columns for simplicity, and you want a single class consisting of both tables.
You can achieve this using <code>table_sql</code> with a SQL query that returns their union, replacing <code>from_table</code> as described for <a href="#class-defined-by-table">table classes</a>.</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#24292E">kb {</span></span>
<span class="line"><span style="color:#D73A49">    class</span><span style="color:#6F42C1"> Customer</span><span style="color:#24292E"> {</span></span>
<span class="line"><span style="color:#24292E">        name.en</span><span style="color:#D73A49">:</span><span style="color:#032F62"> "Customer"</span></span>
<span class="line"></span>
<span class="line"><span style="color:#E36209">        table_sql</span><span style="color:#D73A49">:</span></span>
<span class="line"><span style="color:#032F62">            """</span></span>
<span class="line"><span style="color:#032F62">            (SELECT * FROM movie_db.public.corporate_customer</span><span style="color:#B31D28;font-style:italic">)</span></span>
<span class="line"><span style="color:#6F42C1">                UNION</span></span>
<span class="line"><span style="color:#24292E">               (</span><span style="color:#6F42C1">SELECT</span><span style="color:#24292E"> * </span><span style="color:#6F42C1">FROM</span><span style="color:#6F42C1"> movie_db</span><span style="color:#24292E">.</span><span style="color:#6F42C1">public</span><span style="color:#24292E">.</span><span style="color:#6F42C1">private_customer</span><span style="color:#24292E">)</span></span>
<span class="line"><span style="color:#032F62">            """</span></span>
<span class="line"><span style="color:#032F62">        // These now use $table.column_name, where column_name is the SQL identifie</span><span style="color:#B31D28;font-style:italic">r</span></span>
<span class="line"><span style="color:#6A737D">        //  (which possibly needs to be escaped, depending on the SQL dialect)</span></span>
<span class="line"><span style="color:#6F42C1">        sql</span><span style="color:#D73A49">:</span><span style="color:#032F62"> "$table.id"</span></span>
<span class="line"><span style="color:#6F42C1">        name_sql</span><span style="color:#24292E">.</span><span style="color:#6F42C1">en</span><span style="color:#D73A49">:</span><span style="color:#032F62"> "'[' || $table.id || '] ' || $table.name"</span></span>
<span class="line"><span style="color:#6F42C1">        synonym_sql</span><span style="color:#24292E">.</span><span style="color:#6F42C1">en</span><span style="color:#D73A49">:</span><span style="color:#032F62"> "$table.name"</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">        class</span><span style="color:#6F42C1"> Status</span><span style="color:#24292E"> {</span></span>
<span class="line"><span style="color:#24292E">            name.en</span><span style="color:#D73A49">:</span><span style="color:#032F62"> "Status"</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6A737D">            // Same for attributes of the class, use ${ClassName}.column_name</span></span>
<span class="line"><span style="color:#E36209">            sql</span><span style="color:#D73A49">:</span><span style="color:#032F62"> "${Customer}.status"</span></span>
<span class="line"><span style="color:#24292E">        }</span></span>
<span class="line"><span style="color:#24292E">    }</span></span>
<span class="line"><span style="color:#24292E">}</span></span></code></pre></figure>
<p><code>table_sql</code> also allows filtering, adding or transforming columns and joining other tables, and is thus very powerful.</p>
<p>Other than replacing <code>from_table</code> by <code>table_sql</code> and adapting SQLs based on it, a class defined using a table SQL will behave the same as a <a href="#class-defined-by-table">table class</a>.</p>
<p><code>from_table</code> may also reference a class that defines a <code>table_sql</code>, basing several classes on the same query. The referencing classes inherit its <code>sql</code> and must not define their own.</p>
<aside class="docs-aside docs-aside--note" data-title="Note"><p class="docs-aside__title">Note</p><p>Prefer <a href="#class-defined-by-table">simple table classes</a> over using <code>table_sql</code> if possible, as Veezoo will be able to help you more, for example you can import columns from the table and Veezoo will generate VKL for them.</p></aside>
<h3 id="advanced-class-with-custom-entities-defined-by-a-sql">Advanced: Class with Custom Entities defined by a SQL</h3>
<p>The last way you can define a class is over a SQL query defining the entities, which follows a specific format.</p>
<p>Let's take the example of two tables <code>customer(id, email)</code> and <code>profile(id, customer_id, name)</code>. For whatever reason, we have now two tables with information about a customer. For simplicity sake, let's assume that <code>profile</code> only has one entry per customer.</p>
<p>Now, we don't want to make <code>profile</code> accessible over Veezoo, since it is just extra information that was separated technically in different tables. Our business users have no clue why it is separated and they don't want to care about it.</p>
<p>What we will do instead now is to join both these tables so we can generate entities of the class <code>kb.Customer</code> with nice-looking names.</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">import</span><span style="color:#24292E"> db.postgres.movie_db.public.customer</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">kb {</span></span>
<span class="line"><span style="color:#24292E">    class Customer {</span></span>
<span class="line"><span style="color:#24292E">        name.en: </span><span style="color:#032F62">"Customer"</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6A737D">        // e.g. 00042</span></span>
<span class="line"><span style="color:#24292E">        sql: </span><span style="color:#032F62">"${customer.id}"</span></span>
<span class="line"><span style="color:#24292E">        from_table: customer</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">        entities_custom_sql:</span></span>
<span class="line"><span style="color:#032F62">            ""</span><span style="color:#24292E">"</span></span>
<span class="line"><span style="color:#24292E">            SELECT</span></span>
<span class="line"><span style="color:#24292E">                c.id AS ID,</span></span>
<span class="line"><span style="color:#032F62">                '['</span><span style="color:#24292E"> || c.id || </span><span style="color:#032F62">'] '</span><span style="color:#24292E"> || p.name AS LABEL_EN_MAIN,</span></span>
<span class="line"><span style="color:#24292E">                p.name AS LABEL_EN_1,</span></span>
<span class="line"><span style="color:#24292E">                p.profile_text AS DESCRIPTION_EN</span></span>
<span class="line"><span style="color:#24292E">            FROM</span></span>
<span class="line"><span style="color:#24292E">                customer c JOIN profile p ON c.id = p.customer_id</span></span>
<span class="line"><span style="color:#032F62">            ""</span><span style="color:#24292E">"</span></span>
<span class="line"><span style="color:#24292E">    }</span></span>
<span class="line"><span style="color:#24292E">}</span></span></code></pre></figure>
<p>As you can notice, instead of a <code>name_sql</code> and <code>description_sql</code>, we defined an <code>entities_custom_sql</code>. The presence of <code>entities_custom_sql</code> is what tells Veezoo to generate the entities from the query.</p>
<p>Let's take a closer look at the SQL:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">SELECT</span></span>
<span class="line"><span style="color:#005CC5">    c</span><span style="color:#24292E">.</span><span style="color:#005CC5">id</span><span style="color:#D73A49"> AS</span><span style="color:#24292E"> ID,</span></span>
<span class="line"><span style="color:#032F62">    '['</span><span style="color:#D73A49"> ||</span><span style="color:#005CC5"> c</span><span style="color:#24292E">.</span><span style="color:#005CC5">id</span><span style="color:#D73A49"> ||</span><span style="color:#032F62"> '] '</span><span style="color:#D73A49"> ||</span><span style="color:#005CC5"> p</span><span style="color:#24292E">.</span><span style="color:#005CC5">name</span><span style="color:#D73A49"> AS</span><span style="color:#24292E"> LABEL_EN_MAIN,</span></span>
<span class="line"><span style="color:#005CC5">    p</span><span style="color:#24292E">.</span><span style="color:#005CC5">name</span><span style="color:#D73A49"> AS</span><span style="color:#24292E"> LABEL_EN_1</span></span>
<span class="line"><span style="color:#D73A49">FROM</span></span>
<span class="line"><span style="color:#24292E">    customer c </span><span style="color:#D73A49">JOIN</span><span style="color:#D73A49"> profile</span><span style="color:#24292E"> p </span><span style="color:#D73A49">ON</span><span style="color:#005CC5"> c</span><span style="color:#24292E">.</span><span style="color:#005CC5">id</span><span style="color:#D73A49"> =</span><span style="color:#005CC5"> p</span><span style="color:#24292E">.</span><span style="color:#005CC5">customer_id</span></span></code></pre></figure>
<p>An <code>entities_custom_sql</code> always needs to have in the <code>SELECT</code>:</p>
<ul>
<li>One <code>ID</code> column, coinciding with the <code>sql</code> of the class</li>
<li>At least one <code>LABEL_{LANGUAGE_TAG}_MAIN</code>, which will define the <code>name</code> of entities, similar to a <code>name_sql</code> in the previous cases. Multiple can be provided for different languages.</li>
</ul>
<p><strong>Optional columns:</strong></p>

























<table><thead><tr><th>Column</th><th>Description</th></tr></thead><tbody><tr><td><code>LABEL_{LANGUAGE-TAG}_*</code></td><td>Additional labels used as synonyms, similar to <code>synonym_sql</code>. The <code>*</code> can be any suffix (e.g., <code>LABEL_EN_1</code>, <code>LABEL_EN_CODE</code>).</td></tr><tr><td><code>DESCRIPTION_{LANGUAGE-TAG}</code></td><td>Description for entities, similar to <code>description_sql</code>.</td></tr><tr><td><code>FOR_USER_ROLE</code>, <code>FOR_USER_ROLE_*</code></td><td>User roles for entity-level access control, similar to <a href="/vkl/kb-layer/class/for_user_role_sql"><code>for_user_role_sql</code></a>. If defined but all values are NULL/empty for an entity, that entity will not be created. Use <code>_ALLOW_ALL_</code> to make an entity accessible to all users. The <code>*</code> can be any suffix (e.g., <code>FOR_USER_ROLE_1</code>).</td></tr><tr><td><code>PARENT</code></td><td>Parent entity ID for <a href="/vkl/kb-layer/class/hierarchy-class/">hierarchy classes</a>.</td></tr></tbody></table>
<p>It is important to notice that this SQL is only used to generate entities during sync time, not query time. If you are interested in using custom SQLs during query time, please refer to virtual_table in the <code>database</code> part.</p>
