15:Ta740,<p>The Veezoo Query Language (VQL) acts as a bridge between natural language and SQL. When users pose questions to Veezoo, the intelligent Veezoo model translates these queries into VQL, which is then deterministically transformed into SQL.</p>
<p>VQL offers the same expressiveness as SQL but operates at a higher abstraction level by utilizing the classes and attributes defined in the Veezoo Knowledge Graph instead of directly working on underlying tables and columns.</p>
<p>While viewer-users don't need access to VQL for everyday tasks, creator-users can benefit significantly from understanding VQL, particularly because:</p>
<ul>
<li>
<p>When Veezoo answers a question, it provides both the SQL and the corresponding VQL used. VQL is often shorter and more human-readable.</p>
</li>
<li>
<p>Measures, functions, and rules are defined using VQL, making it an essential tool for creators looking to leverage Veezoo's advanced capabilities.</p>
</li>
</ul>
<h2 id="variables-and-select">Variables and Select</h2>
<p>Let's take a look at a simple VQL query that returns a list of all products:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> product from kb.Product</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(product)</span></span></code></pre></figure>
<p>A typical VQL query starts by defining variables. Similar to many programming languages, variables in VQL can represent different types, such as:</p>
<ul>
<li>a <a href="/vkl/kb-layer/attribute/types/number">number</a>, <a href="/vkl/kb-layer/attribute/types/string">string</a>, or <a href="/vkl/kb-layer/attribute/types/boolean">boolean</a></li>
<li>a <a href="#dates">date</a></li>
<li>a specific <a href="/vkl/kb-layer/entity/">entity</a> of a class</li>
<li>a <a href="/vkl/kb-layer/class">class</a> itself, as in this case <code>var product from kb.Product</code></li>
</ul>
<p>In VQL, a variable like <code>product</code> doesn’t represent a single instance of the class but instead refers to <em>all possible instances</em>. Think of a class in VQL as corresponding to an entire column or table in SQL.</p>
<p>Finally, <code>select(product)</code> specifies what the query will return. This is similar to the <code>SELECT</code> statement in SQL.
There must be one <code>select</code> statement at the end of every VQL query. Subqueries also use <code>select</code> at the end, see the section on <a href="#subqueries">subqueries</a>.</p>
<aside class="docs-aside docs-aside--note" data-title="Note"><p class="docs-aside__title">Note</p><p>The VQL shown to users when answers are generated is not directly translated to SQL but undergoes several rewriting steps: rewriting rules are applied, functions are replaced by their definitions, and <a href="/vkl/kb-layer/class/display_with"><code>display_with</code></a> is added.</p><p>The rewriting happens after the VQL is shown, keeping the shown VQL easier to understand. However, it can make it harder to see how a particular VQL translates to SQL.</p></aside>
<h3 id="showing-attributes">Showing Attributes</h3>
<p>In VQL, if you want to display additional attributes, you can do it like this:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> product from kb.Product</span></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> category from kb.Product.Category</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">category </span><span style="color:#D73A49">=</span><span style="color:#24292E"> product.Category</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(product, category)</span></span></code></pre></figure>
<p>Here, we define a second variable called <code>category</code>, which is of type <code>kb.Product.Category</code>. In the third line, we assign <code>category</code> to represent the categories associated with <code>product</code> using the dot-operator. The expression <code>product.Category</code> indicates that the class represented by <code>product</code> has an attribute or a relationship called <code>Category</code>.</p>
<p>Make sure to explicitly connect the different variables in the VQL. Veezoo won't do that automatically for you.</p>
<p>Note that the dot-operator used here is different from the one in the first two lines, where it is part of the type's path.</p>
<p>This VQL can be simplified to:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> product from kb.Product</span></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> category </span><span style="color:#D73A49">=</span><span style="color:#24292E"> product.Category</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(product, category)</span></span></code></pre></figure>
<p>In this case, the variable type is inferred automatically. The code can be further shortened (as Veezoo would generate it):</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> product from kb.Product</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(product, product.Category)</span></span></code></pre></figure>
<h2 id="filters">Filters</h2>
<p>In most cases, we don't want to just return one or more attributes; we want to filter them based on certain criteria. For example, the following VQL will be generated when asking <em>Show me Orders from the Region West</em>:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> order from kb.Order</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">order.Region </span><span style="color:#D73A49">=</span><span style="color:#24292E"> kb.Order.Region.West</span></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(order)</span></span></code></pre></figure>
<p>The second line here performs the filtering. Instead of overwriting something (as one might expect from other programming languages), we restrict the variable <code>order</code> to only those with a <code>Region</code> equal to the entity <code>kb.Order.Region.West</code>.</p>
<p>Filtering for numeric conditions can be done using mathematical comparisons (e.g., <em>Show orders with a quantity greater than 5</em>):</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> order from kb.Order</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> quantity </span><span style="color:#D73A49">=</span><span style="color:#24292E"> order.Quantity</span></span>
<span class="line"><span style="color:#24292E">quantity </span><span style="color:#D73A49">></span><span style="color:#005CC5"> 5</span></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(order, quantity)</span></span></code></pre></figure>
<h3 id="negation">Negation</h3>
<p>Use the <code>not{}</code> function to negate filters:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> customer from kb.Customer</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">not {</span></span>
<span class="line"><span style="color:#D73A49">  var</span><span style="color:#24292E"> order from kb.Order</span></span>
<span class="line"><span style="color:#24292E">  order.Customer </span><span style="color:#D73A49">=</span><span style="color:#24292E"> customer</span></span>
<span class="line"><span style="color:#24292E">}</span></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(customer)</span></span></code></pre></figure>
<p>Here, all customers without any orders are returned. It filters for no possible value within the curly brackets.</p>
<h3 id="string-filters">String Filters</h3>
<p>For attributes of type string, Veezoo provides the following filter functions:</p>
<ul>
<li><code>starts_with_string()</code></li>
<li><code>contains_string()</code></li>
<li><code>ends_with_string()</code></li>
</ul>
<p>These functions take two arguments: the string to be filtered and the value to compare it to:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> customer from kb.Customer</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> name </span><span style="color:#D73A49">=</span><span style="color:#24292E"> customer.fullName</span></span>
<span class="line"><span style="color:#6F42C1">starts_with_string</span><span style="color:#24292E">(name, </span><span style="color:#032F62">"Lukas"</span><span style="color:#24292E">)</span></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(name, customer)</span></span></code></pre></figure>
<p>Here, we select customers whose full name starts with <em>Lukas</em>.</p>
<p>All of these string filters are case-insensitive.</p>
<h2 id="joins">Joins</h2>
<p>Connecting two classes in VQL, which corresponds to joining two tables in SQL or accessing a column of a class, works similarly to filtering entities. For example, here is the VQL for the question <em>Show me all orders from customers with segment consumer</em>:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> order from kb.Order</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> customer </span><span style="color:#D73A49">=</span><span style="color:#24292E"> order.with_Customer</span></span>
<span class="line"><span style="color:#24292E">customer.Segment </span><span style="color:#D73A49">=</span><span style="color:#24292E"> kb.Customer.Segment.Consumer</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(order, customer)</span></span></code></pre></figure>
<p>In the second line, we connect the order and customer classes, which will join the order and customer tables in SQL. We define the <code>customer</code> variable to be the customers from the orders, i.e. <code>order.with_Customer</code>,  which will be mapped to the <code>customer</code> foreign key column in the order table in SQL.</p>
<p>In the next line, we specify that we only want customers with the segment <code>Consumer</code>. Since the orders and customers are already connected, this filter also affects the orders.</p>
<p>Finally, we return the orders and their customers.</p>
<h2 id="dates">Dates</h2>
<p>VQL has rich support for <a href="/vkl/kb-layer/attribute/types/date">dates</a>, allowing you to filter and convert them to different granularities.</p>
<h3 id="date-filters">Date Filters</h3>
<p>If a class has a <code>date</code> field, filtering for dates can be done similarly to filtering for other numeric values:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> order from kb.Order</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> orderDate </span><span style="color:#D73A49">=</span><span style="color:#24292E"> order.Order_Date</span></span>
<span class="line"><span style="color:#24292E">orderDate </span><span style="color:#D73A49">></span><span style="color:#6F42C1"> date</span><span style="color:#24292E">(</span><span style="color:#032F62">"2022-05-01"</span><span style="color:#24292E">)</span></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(order, orderDate)</span></span></code></pre></figure>
<p>The expression <code>date("2022-05-01")</code> returns a date object for May 1st, 2022.</p>
<p>To filter for dates within a specific period, use the <code>date_in()</code> function:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> order from kb.Order</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> orderDate </span><span style="color:#D73A49">=</span><span style="color:#24292E"> order.Order_Date</span></span>
<span class="line"><span style="color:#6F42C1">date_in</span><span style="color:#24292E">(orderDate, </span><span style="color:#6F42C1">date</span><span style="color:#24292E">(</span><span style="color:#032F62">"2023"</span><span style="color:#24292E">))</span></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(order, orderDate)</span></span></code></pre></figure>
<p>Similarly, the <code>date_in_range()</code> function can be used to filter for dates between a start and end point:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#6F42C1">date_in_range</span><span style="color:#24292E">(</span><span style="color:#6F42C1">date</span><span style="color:#24292E">(</span><span style="color:#032F62">"1995-10-24"</span><span style="color:#24292E">), orderDate, </span><span style="color:#6F42C1">date</span><span style="color:#24292E">(</span><span style="color:#032F62">"2008-05-13"</span><span style="color:#24292E">))</span></span></code></pre></figure>
<h3 id="relative-dates">Relative Dates</h3>
<p>Besides static dates (which refer to a fixed point in time) VQL also offers support for relative dates like <em>this year</em> or <em>last month</em>. This is helpful in keeping dashboards up to date. If a widget is created by asking the question <em>How many orders last week</em>, the widget will show data for the week prior to the current date, instead of always keeping to show data for the week before the question was asked.</p>
<p>Basic relative dates can be expressed using the <code>date()</code> function with special keywords starting with <code>#</code>:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> order from kb.Order</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> orderDate </span><span style="color:#D73A49">=</span><span style="color:#24292E"> order.Order_Date</span></span>
<span class="line"><span style="color:#6F42C1">date_in</span><span style="color:#24292E">(orderDate, </span><span style="color:#6F42C1">date</span><span style="color:#24292E">(</span><span style="color:#032F62">"#thisYear"</span><span style="color:#24292E">))</span></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(order, orderDate)</span></span></code></pre></figure>
<p>These values include:</p>








































<table><thead><tr><th>Current</th><th>Last</th><th>Next</th></tr></thead><tbody><tr><td><code>#thisYear</code></td><td><code>#lastYear</code></td><td><code>#nextYear</code></td></tr><tr><td><code>#thisQuarter</code></td><td><code>#lastQuarter</code></td><td><code>#nextQuarter</code></td></tr><tr><td><code>#thisMonth</code></td><td><code>#lastMonth</code></td><td><code>#nextMonth</code></td></tr><tr><td><code>#thisWeek</code></td><td><code>#lastWeek</code></td><td><code>#nextWeek</code></td></tr><tr><td><code>#today</code></td><td><code>#yesterday</code></td><td><code>#tomorrow</code></td></tr><tr><td><code>#now</code></td><td>—</td><td>—</td></tr></tbody></table>
<p>More complex relative dates can be build up using <code>date_add</code>, e.g. "Number of orders in the last 30 days vs. the same period last year":</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> order from kb.Order</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> orderDate </span><span style="color:#D73A49">=</span><span style="color:#24292E"> order.order_Date</span></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> year </span><span style="color:#D73A49">=</span><span style="color:#24292E"> {</span></span>
<span class="line"><span style="color:#24292E">  # Between </span><span style="color:#005CC5">29</span><span style="color:#24292E"> days ago and today</span></span>
<span class="line"><span style="color:#24292E">  between(orderDate, </span><span style="color:#6F42C1">date_add</span><span style="color:#24292E">(</span><span style="color:#E36209">date</span><span style="color:#24292E">(</span><span style="color:#032F62">"#today"</span><span style="color:#24292E">), -</span><span style="color:#005CC5">29</span><span style="color:#24292E">, </span><span style="color:#6F42C1">periodicity</span><span style="color:#24292E">(</span><span style="color:#032F62">"P1D"</span><span style="color:#24292E">)), </span><span style="color:#6F42C1">date</span><span style="color:#24292E">(</span><span style="color:#032F62">"#today"</span><span style="color:#24292E">))</span></span>
<span class="line"><span style="color:#24292E">} union {</span></span>
<span class="line"><span style="color:#24292E">  # Between </span><span style="color:#005CC5">29</span><span style="color:#24292E"> days ago last year and today last year</span></span>
<span class="line"><span style="color:#24292E">  between(orderDate, </span><span style="color:#6F42C1">date_add</span><span style="color:#24292E">(</span><span style="color:#E36209">date_add</span><span style="color:#24292E">(</span><span style="color:#E36209">date</span><span style="color:#24292E">(</span><span style="color:#032F62">"#today"</span><span style="color:#24292E">), -</span><span style="color:#005CC5">29</span><span style="color:#24292E">, </span><span style="color:#6F42C1">periodicity</span><span style="color:#24292E">(</span><span style="color:#032F62">"P1D"</span><span style="color:#24292E">)), -</span><span style="color:#005CC5">1</span><span style="color:#24292E">, </span><span style="color:#6F42C1">periodicity</span><span style="color:#24292E">(</span><span style="color:#032F62">"P1Y"</span><span style="color:#24292E">)), </span><span style="color:#6F42C1">date_add</span><span style="color:#24292E">(</span><span style="color:#E36209">date</span><span style="color:#24292E">(</span><span style="color:#032F62">"#today"</span><span style="color:#24292E">), -</span><span style="color:#005CC5">1</span><span style="color:#24292E">, </span><span style="color:#6F42C1">periodicity</span><span style="color:#24292E">(</span><span style="color:#032F62">"P1Y"</span><span style="color:#24292E">)))</span></span>
<span class="line"><span style="color:#24292E">}</span></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> retCount </span><span style="color:#D73A49">=</span><span style="color:#6F42C1"> count</span><span style="color:#24292E">(order) </span><span style="color:#6F42C1">by</span><span style="color:#24292E"> (year)</span></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(year, retCount)</span></span></code></pre></figure>
<h2 id="aggregation-functions">Aggregation Functions</h2>
<p>VQL aggregation functions work similarly to SQL:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> order from kb.Order</span></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> profit </span><span style="color:#D73A49">=</span><span style="color:#24292E"> order.Profit</span></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> sumProfit </span><span style="color:#D73A49">=</span><span style="color:#6F42C1"> sum</span><span style="color:#24292E">(profit)</span></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(sumProfit)</span></span></code></pre></figure>
<p>Similar to SQL, you may also perform multiple aggregations in parallel, using the following syntax:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> order from kb.Order</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> profit </span><span style="color:#D73A49">=</span><span style="color:#24292E"> order.Profit</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> (sumProfit, averageProfit, countOrder) </span><span style="color:#D73A49">=</span><span style="color:#24292E"> (</span><span style="color:#6F42C1">sum</span><span style="color:#24292E">(profit), </span><span style="color:#6F42C1">average</span><span style="color:#24292E">(profit), </span><span style="color:#6F42C1">count</span><span style="color:#24292E">(order))</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(sumProfit, averageProfit, countOrder)</span></span></code></pre></figure>
<p>The aggregation functions can also be used directly in the final <code>select</code> statement:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> order from kb.Order</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> profit </span><span style="color:#D73A49">=</span><span style="color:#24292E"> order.Profit</span></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(</span><span style="color:#6F42C1">sum</span><span style="color:#24292E">(profit), </span><span style="color:#6F42C1">average</span><span style="color:#24292E">(profit), </span><span style="color:#6F42C1">count</span><span style="color:#24292E">(order))</span></span></code></pre></figure>
<p>As in SQL, aggregation functions can be grouped by one or more attributes. For example, if we want the <em>Average Profit of Orders by Shipping Mode</em>, instead of calculating the average profit for all orders, we divide the orders into groups based on their shipping mode and then calculate the average per group:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> order from kb.Order</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> shippingMode </span><span style="color:#D73A49">=</span><span style="color:#24292E"> order.Shipping_Mode</span></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(</span><span style="color:#6F42C1">average</span><span style="color:#24292E">(order.Profit) </span><span style="color:#6F42C1">by</span><span style="color:#24292E"> (shippingMode), shippingMode)</span></span></code></pre></figure>
<p>The shipping mode must be included in the <code>select</code> statement (not just in the <code>by</code> clause) so that users can see which case the aggregated numbers represent. Let's look at another example, <em>Average Profit of Orders by Shipping Mode and Region</em>:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> order from kb.Order</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> region </span><span style="color:#D73A49">=</span><span style="color:#24292E"> order.Region</span></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> shippingMode </span><span style="color:#D73A49">=</span><span style="color:#24292E"> order.Shipping_Mode</span></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(</span><span style="color:#6F42C1">average</span><span style="color:#24292E">(order.Profit) </span><span style="color:#6F42C1">by</span><span style="color:#24292E"> (shippingMode, region), shippingMode, region)</span></span></code></pre></figure>
<h3 id="aggregation-over-time">Aggregation Over Time</h3>
<p>A common form of aggregation is over a certain timespan, such as day, week, or year. This involves some extra steps. The following example calculates the <em>Average Discount of Orders by Week</em>:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> order from kb.Order</span></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> week </span><span style="color:#D73A49">=</span><span style="color:#6F42C1"> periodicity</span><span style="color:#24292E">(</span><span style="color:#032F62">"P1W"</span><span style="color:#24292E">)</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> orderDate </span><span style="color:#D73A49">=</span><span style="color:#24292E"> order.Order_Date</span></span>
<span class="line"><span style="color:#6F42C1">project_date</span><span style="color:#24292E">(orderDate, week)</span></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(</span><span style="color:#6F42C1">average</span><span style="color:#24292E">(</span><span style="color:#6F42C1">sum</span><span style="color:#24292E">(order.Discount) </span><span style="color:#6F42C1">by</span><span style="color:#24292E"> (week)))</span></span></code></pre></figure>
<p>The line <code>var week = periodicity("P1W")</code> defines the time duration for aggregation. The variable <code>week</code> is then passed into the <code>project_date()</code> function, where the <code>week</code> periodicity is assigned the week of the <code>Order_Date</code>. Finally, we can aggregate by week.</p>
<h2 id="arithmetic-functions">Arithmetic Functions</h2>
<p>VQL supports arithmetic functions like <code>+</code>, <code>-</code>, <code>/</code>, or <code>*</code> to perform calculations. For example, to calculate the total order value minus the value-added tax:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> order from kb.Order</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(</span><span style="color:#6F42C1">sum</span><span style="color:#24292E">(order.value </span><span style="color:#D73A49">-</span><span style="color:#24292E"> order.</span><span style="color:#005CC5">VAT</span><span style="color:#24292E">))</span></span></code></pre></figure>
<p>Arithmetic functions can also be used with grouped aggregations. Here, we calculate the same value but grouped by month:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> order from kb.Order</span></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> month </span><span style="color:#D73A49">=</span><span style="color:#6F42C1"> periodicity</span><span style="color:#24292E">(</span><span style="color:#032F62">"P1M"</span><span style="color:#24292E">)</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">project_date</span><span style="color:#24292E">(order.order_date, month)</span></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(</span><span style="color:#6F42C1">sum</span><span style="color:#24292E">(order.value) </span><span style="color:#6F42C1">by</span><span style="color:#24292E"> (month) </span><span style="color:#D73A49">-</span><span style="color:#6F42C1"> sum</span><span style="color:#24292E">(order.</span><span style="color:#005CC5">VAT</span><span style="color:#24292E">) </span><span style="color:#6F42C1">by</span><span style="color:#24292E"> (month), month)</span></span></code></pre></figure>
<p>In such cases, both operands need to be aggregated at the same level of granularity.</p>
<h3 id="percentages">Percentages</h3>
<p>To calculate percentages, VQL provides the <code>proportion() {}</code> function. For example, to calculate the percentage of customers who live in Zurich:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> customer from kb.Customer</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> proportion </span><span style="color:#D73A49">=</span><span style="color:#6F42C1"> proportion</span><span style="color:#24292E">(customer) {</span></span>
<span class="line"><span style="color:#24292E">  customer.lives_in </span><span style="color:#D73A49">=</span><span style="color:#24292E"> kb.City.Zurich</span></span>
<span class="line"><span style="color:#24292E">}</span></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(proportion)</span></span></code></pre></figure>
<p>The <code>proportion()</code> function works by calculating the overall count or sum as the denominator, and then applying the filter inside the curly braces to calculate a restricted count or sum as the numerator.</p>
<p>This means that, for example, if an <code>order</code> has a <code>value</code> and a <code>VAT</code>, it is NOT possible to use this function to calculate what percentage of the value the VAT represents, since <code>order.VAT</code> is not a subset of <code>order.value</code>.</p>
<p>The <code>proportion() {}</code> function can also be used with grouped data. For instance, to calculate the same percentage but grouped by customer segment:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> customer from kb.Customer</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> segment </span><span style="color:#D73A49">=</span><span style="color:#24292E"> customer.customer_segment</span></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> proportion </span><span style="color:#D73A49">=</span><span style="color:#6F42C1"> proportion</span><span style="color:#24292E">(customer) {</span></span>
<span class="line"><span style="color:#24292E">  customer.lives_in </span><span style="color:#D73A49">=</span><span style="color:#24292E"> kb.City.Zurich</span></span>
<span class="line"><span style="color:#24292E">} </span><span style="color:#6F42C1">by</span><span style="color:#24292E"> (segment)</span></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(segment, proportion)</span></span></code></pre></figure>
<h2 id="union">Union</h2>
<p>In many cases, users want to filter for multiple possible options. For example, <em>Show customers from Zurich and Ljubljana</em> or <em>Show premium customers and customers with high cancellation risk</em>. To achieve this, Veezoo provides two versions of the <code>union</code> function.</p>
<p>In simpler scenarios, where you want to combine different entities of the same class (as in the first example), you can do it like this:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> customer from kb.Customer</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> city </span><span style="color:#D73A49">=</span><span style="color:#6F42C1"> union</span><span style="color:#24292E">(kb.City.Zurich, kb.City.Ljubljana)</span></span>
<span class="line"><span style="color:#24292E">customer.lives_in </span><span style="color:#D73A49">=</span><span style="color:#24292E"> city</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(city, customer)</span></span></code></pre></figure>
<p>Here, <code>var city</code> represents the union of Zurich and Ljubljana, and the following line filters out all customers who do not live in either city. The <code>union</code> function can include any number of entities.</p>
<p>For more complex cases, where you want to combine different conditions, the syntax changes. In the following case we want to select customers, which are either premium customers, or have a high cancellation risk associated with them:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> customer from kb.Customer</span></span>
<span class="line"></span>
<span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> caseIdentifier </span><span style="color:#D73A49">=</span><span style="color:#24292E"> {</span></span>
<span class="line"><span style="color:#24292E">  customer.is_premium </span><span style="color:#D73A49">=</span><span style="color:#005CC5"> true</span></span>
<span class="line"><span style="color:#24292E">} union {</span></span>
<span class="line"><span style="color:#24292E">  customer.cancellation_risk </span><span style="color:#D73A49">=</span><span style="color:#24292E"> kb.Customer.cancellation_risk.high</span></span>
<span class="line"><span style="color:#24292E">}</span></span>
<span class="line"></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(caseIdentifier, customer)</span></span></code></pre></figure>
<p>This version of the <code>union</code> function does two things:</p>
<ul>
<li>It restricts <code>customer</code> to those who are either premium OR have a high cancellation risk.</li>
<li>It creates <code>var caseIdentifier</code>, which contains labels for all the possible cases that are part of the union. This is also selected, allowing the user to see why a particular customer is shown (e.g., <em>Yanick Brecher</em> is shown because he is a <em>premium customer</em>).</li>
</ul>
<h2 id="subqueries">Subqueries</h2>
<p>VQL supports subqueries, which allow you to break down complex queries into smaller, more manageable parts. Subqueries are particularly useful for improving readability, avoiding code duplication, and creating intermediate results that can be reused multiple times within a query.</p>
<h3 id="types-of-subqueries">Types of Subqueries</h3>
<p>VQL offers two ways to work with subqueries:</p>
<h4 id="inline-subqueries">Inline Subqueries</h4>
<p>Inline subqueries are defined using curly braces <code>{ ... }</code> and can be used directly with the <code>from</code> keyword:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#D73A49">var</span><span style="color:#24292E"> customerRevenue from {</span></span>
<span class="line"><span style="color:#D73A49">  var</span><span style="color:#24292E"> order from kb.Order</span></span>
<span class="line"><span style="color:#D73A49">  var</span><span style="color:#24292E"> customer </span><span style="color:#D73A49">=</span><span style="color:#24292E"> order.Customer</span></span>
<span class="line"><span style="color:#D73A49">  var</span><span style="color:#24292E"> revenue </span><span style="color:#D73A49">=</span><span style="color:#6F42C1"> sum</span><span style="color:#24292E">(order.Revenue) </span><span style="color:#6F42C1">by</span><span style="color:#24292E"> (customer)</span></span>
<span class="line"><span style="color:#6F42C1">  select</span><span style="color:#24292E">(customer, revenue)</span></span>
<span class="line"><span style="color:#24292E">}</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E">customerRevenue.revenue </span><span style="color:#D73A49">></span><span style="color:#005CC5"> 1000</span></span>
<span class="line"><span style="color:#6F42C1">select</span><span style="color:#24292E">(customerRevenue.customer, customerRevenue.revenue)</span></span></code></pre></figure>
<h4 id="named-subqueries-ctes">Named Subqueries (CTEs)</h4>
<p>Named subqueries work similarly to Common Table Expressions (CTEs) in SQL. They are defined at the beginning of a query using the <code>query</code> keyword and can be reused multiple times:</p>
<figure class="docs-code"><pre class="shiki github-light" style="background-color:#fff;color:#24292e" tabindex="0"><code><span class="line"><span style="color:#24292E"># Find customers who have placed more orders than the average</span></span>
<span class="line"></span>
<span class="line"><span style="color:#24292E"># First, calculate the number </span><span style="color:#D73A49">of</span><span style="color:#24292E"> orders per customer</span></span>
<span class="line"><span style="color:#24292E"># This subquery will be used multiple times</span></span>
<span class="line"><span style="color:#24292E">query customerOrderCounts </span><span style="color:#D73A49">=</span><span style="color:#24292E"> {</span></span>
<span class="line"><span style="color:#24292E">  var order from kb.Order</span></span>
<span class="line"><span style="color:#24292E">  var customer </span><span style="color:#D73A49">=</span><span style="color:#24292E"> order.Customer</span></span>
<span class="line"><span style="color:#24292E">  var orderCount </span><span style="color:#D73A49">=</span><span style="color:#6F42C1"> count</span><span style="color:#24292E">(order) </span><span style="color:#6F42C1">by</span><span style="color:#24292E"> (customer)</span></span>
<span class="line"><span style="color:#6F42C1">  select</span><span style="color:#24292E">(</span><span style="color:#E36209">customer</span><span style="color:#24292E">, </span><span style="color:#E36209">orderCount</span><span style="color:#24292E">)</span></span>
